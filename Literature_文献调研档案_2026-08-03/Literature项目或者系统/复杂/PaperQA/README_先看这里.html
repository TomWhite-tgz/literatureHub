一句话结论

PaperQA 不是几个互不相关的项目，而是一条连续演进的科学文献 Agent 主线：

PaperQA / LitQA v0（2023）
        ↓
LAB-Bench / LitQA2 + PaperQA2（2024）
        ├─ WikiCrow：批量写带引用的综述
        ├─ ContraCrow：跨论文寻找矛盾
        └─ Aviary：把 LitQA2 做成可训练、可评测的 Agent 环境
        ↓
开源仓库 v5+ 统称 PaperQA2；2025-12 改用日期版本号
        ↓
PaperQA3 / Edison Literature（2026）
        └─ 同时作为 Edison Literature 和 Kosmos 的文献检索底层

inproxima/paperqa 是从 Future-House/paper-qa fork 出来的副本，不是另一条 PaperQA 技术路线。其归档 HEAD 1bde36c 也存在于官方仓库历史中；当前官方主仓库仍是 Future-House/paper-qa。

发展时间线

时间 名称与资料 这一阶段真正增加了什么
2023-02 PaperQA 开源仓库初始提交 从本地科学论文中检索、筛证据、生成带引文回答。
2023-12 PaperQA v1 论文、LitQA v0、第一版 WikiCrow 把 RAG 拆成 Agent 可调用的 SEARCH → GATHER_EVIDENCE → ANSWER_QUESTION；允许根据中间结果再次检索。LitQA v0 有 50 道必须检索全文才能可靠回答的问题。
2024-07 LAB-Bench 将 LitQA 扩展为 LitQA2，并与图表理解、数据库操作、序列推理等任务组成 2,400+ 题的生物研究能力评测集；公开部分已归档。
2024-09 PaperQA2 论文；代码发布 v5.0.0 关键升级是 Agent 式迭代查询扩展、LLM 重排与 contextual summarization（RCS）、沿引用图补充论文，以及更丰富的文献元数据。论文同时评测问答、WikiCrow 综述和 ContraCrow 矛盾发现。
2024-12 Aviary 把 LitQA2 等科学任务包装为 Agent 环境，并研究训练/优化工具调用策略；它是 PaperQA2 复现和 Agent 训练支线，不是 PaperQA 的替代品。
2025-03 RAG-QA Arena Science 评测博客 FutureHouse 将 PaperQA2 与其他 RAG 系统作横向比较。该外部基准的论文与代码也一并归档，便于判断官方宣传所依据的测试。
2025-12 PaperQA 开源仓库改为 CalVer paper-qa >= 5 仍称 PaperQA2，但 Git tag 从 v5.x 变成 v2025.12.17 等日期版本。同期加入表格、图片、公式、非英文、Office 文档及 Docling/Nemotron Parse 等读取能力。
2026-02 PaperQA3 / Edison Literature Agent 可按需查看图、表和页面，能处理论文、专利和临床试验；不再强制遵循 PaperQA2 的严格回答循环，而是让现代 reasoning LLM 自行检查文档、复查片段并决定何时结束。它也是 Kosmos 的文献检索底层。
2026-02～05 LABBench2 近 1,900 个更贴近实际研究的任务；其中 LitQA3、FigQA2、PatentQA、TrialQA 被用于 PaperQA3/Edison Literature 的公开评测。

名字为什么容易混乱

  • 学术论文中的 PaperQA v1 / PaperQA2 / PaperQA3 是算法代际。
  • Python 包曾按语义版本发布：官方人为规定 paper-qa >= 5 叫 PaperQA2。
  • 2025-12 后包改用日期版本，例如 v2026.02.16；这个版本号不是“PaperQA 2026”这篇论文。
  • 截至本次归档，PaperQA3 的正式公开说明是 Edison Labs 研究博客，底层开源链接仍指向同一个 Future-House/paper-qa 仓库；没有发现一篇单独命名为 PaperQA3 的 arXiv 论文或独立代码仓库。
  • Edison Literature 是面向用户的 Agent/产品名，PaperQA3 是其底层算法代际；生产系统还包含大规模索引、授权全文、内部元数据服务和推理基础设施，不能与 GitHub 包完全画等号。

算法主线：到底怎样工作

PaperQA v1

问题
  ↓
SEARCH：LLM 生成/改写关键词，在大语料中找论文
  ↓
GATHER_EVIDENCE：解析全文，在页/片段级做语义检索并形成带出处的证据
  ↓
ANSWER_QUESTION：对证据排序、压缩并生成带页码/文献引用的答案
  ↖──────── 信息不足时，Agent 可换词再搜 ────────┘

它使用 Semantic Scholar 的元数据和引用图，但并非“把问题交给 Semantic Scholar 就结束”。Semantic Scholar 是候选论文、元数据和引用关系的来源之一；全文获取、切块、嵌入检索、证据摘要、重排、循环控制和最终回答由 PaperQA 完成。

PaperQA2

核心不是简单地换了向量模型，而是扩大 Agent 在检索过程中的决策空间：

  1. LLM 根据问题发起关键词搜索，把候选论文加入当前状态。
  2. 对候选全文切块、检索，再让 LLM 针对当前问题给片段打分并写“上下文化摘要”（RCS）。
  3. Agent 检查已有证据，可改写查询、继续搜索、读取引用/被引论文，或清理较差证据。
  4. 证据足够后，对高分上下文再排序并生成带可追溯引文的答案。
  5. 同一套工具通过换提示词和设置，能执行普通问答、WikiCrow 综述或 ContraCrow 矛盾检测。

PaperQA3 / Edison Literature

它保留“Agent 主动检索和核验证据”的思想，但有三项结构性变化：

  • 多模态：论文进入候选集后，Agent 决定何时把相关图、表、公式或页面图像放入上下文，而不是把所有图片一次性塞给模型。
  • 检索范围：产品侧覆盖论文、专利和临床试验，并结合撤稿、期刊质量、专利来源国等元数据判断来源可信度。
  • 循环控制更自由：移除 PaperQA2 较严格的生成 harness；LLM 可以查看文档、复查片段、放大图片，并自行决定何时已有足够证据。High Effort 主要增加 thinking token 预算及相关超参数。
