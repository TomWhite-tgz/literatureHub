PaSaMaster 深读评价（2026-08-02）

分类：包装的好看没实质（真实存在的工程产品 + 严重包装的论文；零代码，不可验证，不可复现）。

  • 论文：arXiv:2605.14306v3，24 页 Nature 排版，上海交大 + SciLand（公司）+ 浙大；无附录/补充材料
  • code/ 目录：仅 README（102 行产品导流页）+ 3 张图，0 行代码；导流至闭源在线服务 scimaster.bohrium.com 和 npm 的 scimaster-cli（闭源 API 的客户端封装）

方法实质：11 个编号公式无一承载算法创新

  1. "递归自演化检索" = 公式(5) 一条 Reflexion 式反思：LLM 看完本轮排序结果后改写检索策略进入下一轮。既不递归（是迭代）也不自演化（跨 query 无任何更新——无权重更新无持久记忆）；实测只跑 3 轮，GT 命中 Round 0→2 仅 +13%（Fig.3b），绝大部分性能来自第 0 轮基础检索。Reflect prompt、轮数策略、Navigator 用什么模型——全文从未说明。
  2. "零幻觉排序" = 构造上必然成立的同义反复：所有数据库检索系统天然如此（Table 2 里四个非 LLM baseline 幻觉率同为 0）。公式(8)(9) 是小学算术级"形式化"。
  3. "规划/检索分离" = 把"工具分两类""多路召回取并集"写成编号公式（伪形式化/notation dressing）。
  4. 唯一有实质工程量的：1.6 亿论文三层语料库 + Scorer 蒸馏（teacher 未命名、数据不公开、超参缺失）——但细节全部不公开。

实验严谨性

  • Benchmark 循环性（严重）：p.16 明确写候选池构建用了 "PaSaMaster's native search engine"——GT 覆盖被自家引擎塑造，Recall 天然偏向自家系统；benchmark 公开而系统闭源在线，无法排除服务端针对 244 题调优。
  • 稻草人 baseline：Google Scholar F1=1.39、"16.5× 提升"来自把数十词自然语言查询原样喂关键词引擎。
  • 蹭名 PaSa 却不与 PaSa 比较：Table 1 把 PaSa 列为 Level-3 代表，Table 2 主实验中 PaSa 缺席。
  • LLM baseline 用通用 web 搜索 vs 自家 1.6 亿论文定制语料——资源不对等，胜出可能主要来自语料基建而非"自演化"。
  • 无消融、无统计显著性（244 题单次运行无置信区间）；$0.05/query 与 "1% of GPT-5.2 cost" 不可审计。

红旗清单

  • 自封 "Level 4" 范式（自造五级演化论并独占最高级）；"first multidisciplinary benchmark" 与自己引用的 LitSearch 等矛盾。
  • 语料规模同一论文内自相矛盾：Fig.1a/README 写 "1.7 Billion"，p.13 写 "over 160 million"——差一个数量级。
  • 产品营销痕迹：公司作者、Bohrium 商业平台、npm CLI 导流、GitHub 仓库以 README 广告页与"开源"观感刻意混淆。
  • 除 benchmark 数据集（HF 上真实公开）外，论文每一个数字都不可复验。

残余价值

PaSaMaster-Bench（HF 公开）可作评测集用；scimaster-cli / MCP 作为检索工具可用。作为研究材料只有一篇 PDF 和一个 API 端点。
