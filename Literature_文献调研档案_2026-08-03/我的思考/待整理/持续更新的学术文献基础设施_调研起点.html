持续更新的学术文献基础设施：调研起点

1. 暂定研究对象

面向持续增长的科学文献，构建包含全文、元数据、版本、引用图和检索索引的动态文献基础设施，并在其上运行：

  • 文献搜索与推荐；
  • 全文问答；
  • 文献综述；
  • 研究趋势跟踪；
  • 科研 Agent；
  • 研究想法生成与验证。

可用于检索和描述该方向的暂定名称：

Continually Updated Scholarly Knowledge Infrastructure for Literature Agents

相关但不完全等价的名称：

  • Scientific Digital Library
  • Scholarly Data Infrastructure
  • Academic Literature Infrastructure
  • Scholarly Knowledge Graph
  • Scientific Literature Retrieval
  • Agentic Literature Search
  • Living Literature Review
  • Continuous Evidence Synthesis

研究定位

本方向有两个层次，二者都需要调研，但作用不同：

主研究问题
    └── 动态知识环境中的 Literature Agent
        Agent如何发现、选择、更新、检索和使用持续到达的论文

必要支撑
    └── 文献管理与数据基础设施
        全文、元数据、版本、引用图、索引、血缘和增量更新

面向 ICLR、NeurIPS、ICML、KDD、VLDB 等会议时，不应仅将工作定义为“构建论文库”。需要将文献管理能力转化为可研究的问题，例如：

  • 有限预算下，Agent 应选择保存和索引哪些新论文？
  • Retriever 是否应优化最终科研任务效用，而不是局部文本相似度？
  • 如何在论文持续到达、修订和撤稿时保持 Agent 知识新鲜？
  • 如何联合全文、引用图、时间和用户研究轨迹进行检索？
  • 如何评价动态文献环境中的新鲜度、覆盖率、引用正确性和任务表现？
  • 如何为持续变化的 Agent 知识库提供可追溯、可复现的查询结果？

2. 问题的组成

数字图书馆
    └── 论文、元数据、版本、开放获取和长期保存

数据库系统
    └── 增量更新、混合索引、向量管理、数据血缘和一致性

信息检索
    └── 召回、排序、推荐、引用图搜索和检索评测

科学文本处理
    └── PDF解析、章节识别、引用解析、图表抽取和信息抽取

科研知识图谱
    └── Paper、Method、Dataset、Task、Metric、Result、Claim之间的关系

研究 Agent
    └── 查询规划、多步搜索、阅读、证据整合、引用和综述

持续证据更新
    └── 发现新论文、判断是否改变已有结论、更新综述

研究主线与支撑层的关系：

层次 主要作用 潜在投稿方向
Agent、学习与评测 定义任务、策略、奖励、记忆和端到端能力 ICLR、NeurIPS、ICML
检索、推荐与图挖掘 文献召回、排序、新论文发现、动态图建模 KDD、SIGIR、WWW、WSDM

文献管理基础 元数据、PDF、解析、去重、开放获取、数字保存 JCDL、TPDL；同时支撑上述三层

3. 不应将文献库等同于 Embedding 库

完整文献库至少包含：

  1. 原始论文；
  2. 规范化元数据；
  3. 论文版本关系；
  4. 结构化全文与文本块；
  5. 图、表及补充材料；
  6. 关键词索引；
  7. Embedding 索引；
  8. 引用关系；
  9. 数据来源和处理血缘；
  10. 可重建索引所需的配置。

Embedding 是派生索引，不是不可替代的源数据。

原始 PDF / HTML
        ↓
规范化元数据与版本
        ↓
结构化全文、章节、段落、图表
        ↓
BM25 / Embedding / Citation Graph
        ↓
Search / QA / Recommendation / Agent

4.9 面向目标会议的四条主线

A. Budgeted Self-Updating Literature Agent

任务：

输入：
    持续到达的新论文流
    当前Agent文献库
    用户研究兴趣和历史任务
    有限存储、Embedding、LLM和时间预算

动作：
    忽略论文
    只保存元数据
    下载并解析全文
    更新已有论文版本
    替换或归档旧论文
    重新组织索引

目标：
    最大化未来搜索、QA、综述和科研任务表现
    同时控制存储、计算和API成本

核心研究点：

  • Knowledge acquisition policy；
  • Budgeted memory management；
  • Continual learning；
  • Temporal generalization；
  • 新旧知识冲突；
  • 摄取决策对未来任务的长期价值；
  • Agent策略与Retriever联合优化。

主要目标：ICLR、NeurIPS、ICML。

B. Agent-Centric Literature Retrieval

传统 Retriever 优化查询与文档的局部相关性；Agent-centric Retriever 应优化文献对最终任务的效用。

文献效用可以包括：

  • 是否提高最终答案正确率；
  • 是否增加新的证据维度；
  • 是否消除或暴露证据冲突；
  • 是否帮助 Agent 生成下一步检索词；
  • 是否提高文献综述覆盖率；
  • 是否支持最终主张并提供可验证引用。

主要目标：ICLR、NeurIPS、SIGIR、ACL、EMNLP。

C. Evolving Scholarly Graph Mining

数据：

论文全文
+ 引用图
+ 作者和机构图
+ Method/Dataset/Benchmark实体
+ 发表与更新时序
+ 用户阅读、收藏和查询轨迹

任务：

  • 新论文冷启动推荐；
  • Emerging topic detection；
  • 研究方向演化建模；
  • 方法、数据集和Benchmark关系抽取；
  • 个性化研究兴趣更新；
  • 在缺少引用信号时评价新论文价值；
  • 从文献流中发现潜在研究空白。

主要目标：KDD、WWW、WSDM、SIGIR。

D. Dynamic Multimodal Literature Data System

需要统一管理：

PDF与结构化全文
+ Chunk
+ 图片与表格
+ 多版本Embedding
+ 引用图
+ 元数据
+ Agent查询和证据轨迹

系统研究点：

  • 增量解析与Chunk级更新；
  • 关键词、向量、图和元数据的混合查询；
  • Embedding模型在线迁移；
  • 多版本论文与time-travel query；
  • RAG数据血缘和结果可复现；
  • Agent工作负载驱动的索引和查询优化；
  • 持续更新时的一致性、吞吐、延迟和成本。

主要目标：VLDB、SIGMOD、ICDE、CIDR。

4.10 文献管理仍然必须研究

文献管理不是主贡献时，也决定系统能否工作和实验是否可信。必须回答：

  • 文献从哪里持续获得，使用许可是什么？
  • DOI、arXiv、OpenReview和正式出版版如何归并？
  • 原始文件、解析结果、Chunk和Embedding如何建立稳定ID？
  • 论文更新时，哪些数据需要重算？
  • 撤稿、错误版本和失效引用如何传播到Agent？
  • 每个答案使用了哪个论文版本、解析器和Embedding模型？
  • 索引能否由原始文件和配置完全重建？

因此，JCDL、S2ORC、OpenAlex、S2AG、ORKG等工作保留在调研范围内，但作为数据与系统基础，而不是默认的研究主线。

12. 需要回答的核心研究问题

任务与研究贡献层

  • 能否将持续到达的论文流定义为一个可复现的动态科研环境？
  • 文献摄取能否建模为带有存储、计算和时间预算的序列决策问题？
  • 能否使用未来搜索、QA或综述表现作为知识摄取策略的长期奖励？
  • Retriever能否直接优化Agent的最终任务效用，而不是query-document相似度？
  • 能否构造具有严格时间切分、论文版本和到达顺序的Benchmark？
  • 如何分别衡量knowledge freshness、coverage、task utility、citation correctness和cost？
  • 相比“保存全部论文”“按相似度保存”和“固定时间窗口”，学习型策略是否稳定提升？
  • 贡献主要属于新任务、新算法、新系统，还是三者的组合？

数据层

  1. 是否已有适合个人或实验室部署的持续更新学术文献基础设施？
  2. S2ORC、S2AG、OpenAlex分别能提供哪些数据，更新延迟如何？
  3. 如何合法、稳定地获得开放全文？
  4. 如何表示同一工作的多个版本？
  5. 如何保存解析结果，使索引可以重建？

检索层

  1. 论文级召回应使用标题摘要、全文、引用图还是混合检索？
  2. Chunk级检索应在全库进行，还是先检索论文再检索Chunk？
  3. 如何评价研究问题对应的论文集合是否完整？
  4. 新论文没有引用数据时，如何避免被排序系统忽略？
  5. 如何利用正负种子论文建立个性化研究兴趣模型？

Agent层

  1. Agent的工具应是搜索API、全文阅读、引用遍历还是数据库查询？
  2. Agent何时应改写查询、沿引用图扩展或停止搜索？
  3. Agent如何区分“没有找到证据”和“结论为否”？
  4. 如何保证长篇综述中的每个主张均有正确引用？
  5. 如何评价 Agent 相比固定检索流程的真实增益？

更新层

  1. 每日新增论文如何进入候选层、Watchlist和核心全文层？
  2. 哪些事件触发重新解析和重新Embedding？
  3. 更换解析器、Chunk策略或Embedding模型时如何迁移？
  4. 如何处理撤稿、失效结论和错误引用？
  5. 如何记录每个答案依赖的数据与模型版本？

建议的规模分层：

层次 数据规模 保存内容
Candidate Catalog 10万～50万篇 标题、摘要、元数据、引用、摘要向量
Watchlist 1万～3万篇 高相关元数据、推荐状态、可能的全文链接
Core Full-text 3,000～5,000篇 PDF、解析全文、Chunk、向量、图表

每日流程：

数百篇新候选
    ↓ 分类和关键词过滤
约200篇
    ↓ 摘要向量排序
约50篇
    ↓ LLM或规则精排
约10篇
    ↓ 下载与质量检查
约5篇进入核心全文库

14. 调研时避免的混淆

  • 不要把参考文献管理器等同于科学文献数据基础设施。
  • 不要把向量数据库等同于完整文献库。
  • 不要把学术搜索引擎等同于全文问答系统。
  • 不要把单轮 RAG 等同于文献搜索 Agent。
  • 不要把生成引用格式等同于引用事实正确。
  • 不要把引用次数等同于新论文质量。
  • 不要把 arXiv、OpenReview和正式出版版本计为不同工作。
  • 不要让数字图书馆和传统文献管理工作主导问题定义。
  • 不要忽略文献管理；数据错误、版本错误和索引不可追溯会直接破坏上层实验。
  • AI、KDD和VLDB相关工作是核心阅读；数字图书馆、IR、知识图谱和循证研究用于补全必要基础。
  • 不要只搜索 paper management；该词主要召回个人文献管理工具。
