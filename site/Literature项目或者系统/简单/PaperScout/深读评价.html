PaperScout 深读评价（2026-08-02）

分类：简单（真做了训练，但"PSPO 新算法"是 GSPO + turn 级 GAE 的组合重命名；复现性为零）。

  • 论文：arXiv:2601.10029v2，USTC，18 页
  • 深读方式：论文全文 + arft（~3.35k 行）+ recipe/paper_search（~1k 行）全部代码，抽查 vendored verl 关键实现

核心红旗：论文公式与实现不符

  • 论文式(5) 写 PSPO 序列重要性比是 token 比值普通连乘（无长度归一化）。
  • 代码里没有任何名为 pspo 的 policy loss；唯一训练脚本 examples/run_qwen3-4b-mlflow-dbs.sh:42 白纸黑字 loss_mode=gspo，直接调 verl 现成的 GSPO 损失（长度归一化几何平均）。
  • 旁证：clip 超参 ε=3e-4/4e-4 正是 GSPO 的典型量级，用论文的连乘比会把一切剪掉。论文公式是对实际所用 GSPO 的美化转写。
  • 脚本里内部项目名是 FALCON / AgentRFT-PaperSearch；PSPO/PaperScout 是投稿包装。

真实自研的部分

  • turn 级 GAE（arft/core_algos.py:29-108）：每个 response 折叠为一个动作，step 奖励=token 奖励求和，critic 只在动作起点训练，(trajectory, step) 网格上标准 GAE 递归。合理的多轮 agent RL 工程适配，但社区已有大量类似做法，非新数学。
  • 训练主循环（ray_agent_trainer.py 954 行）、异步 rollout（agent_flow.py 1044 行）、检索环境客户端+奖励逻辑是真实工程。

其他问题

  1. 未披露的奖励整形：代码默认 0.4 阈值二值化（论文式(2)写的是连续分数求和）+ 工具成本项 0.1/0.05（论文未提）。
  2. POMDP 建模是话术：无任何利用部分可观测性的机制；观测还被本地 zip 缓存悄悄过滤（utils.py:236-238）。
  3. 评测弱：RL 算法对比只在 50 条 RealScholarQuery 上做，PSPO 比 GSPO 只高 1.7pt，无方差无显著性；AutoScholarQuery 测试集筛到 112 条。scaffold 本身贡献大头（未训练 Qwen3-Max 已接近训练后 4B）。
  4. 循环依赖 PaSa 生态：benchmark、reward model（pasa-7b-selector）、对比基线全来自 PaSa，却宣称 "first autonomous paper search agent"（PaSa crawler 本身就是自主 RL agent，站不住）。
  5. 复现性为零：检索环境服务端（localhost:8765 Milvus/ar5iv 服务）缺失；硬编码私有路径 /data/tingyue/... import 即崩；示例脚本自身跑不通（未启用 reward model）；无数据、无权重、无评测脚本；单 squash commit。
  6. 论文若干组件在代码中缺席或默认关闭：token 级 PPO 基线定义后从未调用（Table 3 的 PPO 行无法复现）；return normalization 默认关闭且实现与论文表述不符；"pool 三轮不变即终止"不存在（实际 max_steps=5）。
