Idea 生成系统 横向可视化

八篇精读论文（CoI · Deep Ideation · SciMON · ResearchAgent · SciPIP · CycleResearcher · VirSci · Tree-of-Debate）用一套统一的视觉语言拆开：文献从哪进、知识怎么组织、idea 怎么生成、新颖性在哪一环保障、最后谁来评判。

① 总范式：五个槽位 ② 三大类 + 一个评估件 ③ 大类A：结构增强 ④ 大类B：训练内化 ⑤ 大类C：社会模拟 ⑥ 评估件：辩论树 ⑦ 全维度矩阵 ⑧ 共同软肋
输入 文献库 / 语料 知识组织（结构） LLM 生成（prompt） 训练 / 权重 评审 / 打分 新颖性检查 输出 评估协议

全页所有流程图共用上面这套颜色 —— 同一个颜色 = 同一个角色，因此各方法的差异可以直接用眼睛扫出来。

① 总范式：一条流水线，五个槽位

The Universal Paradigm

所有「文献 → idea」系统都在填同一条流水线的五个槽位。方法与方法的全部区别，就是每个槽位里填了什么、以及哪个槽位空着。

槽位1 · 输入用户给什么：主题？种子论文？背景段落？关键词？参考文献？
→
槽位2 · 知识组织文献被变成什么形态：链 / 图 / KG / 矩阵 / 训练语料 / 人设
→
槽位3 · 生成机制谁产出 idea：prompt 编排 / 训练好的权重 / 多 agent 讨论
→
槽位4 · 新颖性保障事前分工 / 事中打分 / 事后查重 / 没有
→
槽位5 · 评估协议LLM 裁判 / 人评 / 对照库指标 / 辩论树

输出物（一句话 idea / 三段式 proposal / 完整论文 / 对比报告）由五个槽位的填法共同决定。

② 八篇论文分成几大类？

Taxonomy

按「文献知识最终栖身在哪里」这个最根本的分歧，八篇分成三个生成大类 + 一个评估件。槽位②（知识组织）的形态决定大类归属。

大类 A · 结构增强生成

文献 → 显式结构（链/图/KG/矩阵）→ 塞进 prompt。
知识活在「上下文」里；模型本身不动。
▸ CoI —— 结构 = 引用演化链 ▸ Deep Ideation —— 结构 = 关键词共现图 ▸ SciMON → ResearchAgent → SciPIP —— 结构 = 实体/KG 检索（一条演化线）

大类 B · 训练内化生成

文献 → 训练语料 → 蒸进模型权重。
知识活在「参数」里；推理时不再需要检索。
▸ CycleResearcher —— SFT + 评审模型做 reward 的偏好优化

大类 C · 社会模拟生成

文献 → agent 人设 + 时间对照库 → 多智能体讨论。
知识活在「社会过程」里；idea 是互动的涌现物。
▸ VirSci —— 真实作者档案 role-play 的虚拟科研团队

补 · 评估件（不产 idea）

这条线缺「事后怎么判断两个 idea/论文谁更新颖」的环节。
▸ Tree-of-Debate —— 论文对 → 辩论树 → 相对新颖性判断

2.1定位地图：两个决策轴上的八篇论文

横轴 = 知识载体（越靠右，知识离 prompt 越远、越沉进系统内部）；纵轴 = 新颖性干预时机（越靠上越偏"事后检查"，越靠下越偏"事前设计"）。右上和右下两个象限基本空着 —— 那是没人做过的组合。

位置为定性判断（依据各篇精读页的新颖性机制与知识组织方式），用于看格局而非精确坐标。

这张地图上的两个空格就是机会：① 事后查重 × 训练内化（生成后用独立检索器兜底，再回灌训练）；② 事前设计 × 训练内化（把 SciPIP 式"双路分工"变成训练目标而非 prompt 技巧）。三个大类目前互不通讯：结构派不懂训练，训练派不做检索，模拟派自成一体。

③ 大类 A · 结构增强生成

Structure-Augmented

五篇论文共享同一个骨架，区别只在「文献被组织成什么结构」这一层。先看骨架，再看三种结构形态，最后逐篇拆流程。

文献库S2 / 顶会语料
→
结构化组织 ★分歧点链 / 共现图 / KG / 共现矩阵
→
上下文组装 + LLM prompt零训练，编排 GPT-4 系列
→
idea一句话 → 三件套 → 五个带细节段落

共同软肋也来自骨架本身：增益有多少来自结构、多少来自底层 LLM，五篇都没有拆干净（ResearchAgent 的"随机材料也涨分"是最直接的证据）。

3.2Deep Ideation · 检索从"一次性"变成"图上游走"

10.7 万篇顶会论文LLM 每篇抽 3–4 关键词

⑤ 大类 C · 社会模拟生成

Social Simulation

唯一代表：VirSci（ACL 2025 Main）。知识不进结构也不进权重，进「人」：真实作者档案变成 agent 人设，真实合作网络决定谁和谁讨论，idea 是社会互动的产物。

独到：首个真实作者数据驱动的学术协作模拟；时间切分对照库（B_past/B_con）是可复用的评测范式；还拿 Science of Science 文献做外部效度检验（8人×5轮达峰、50% 新鲜度最优、多样性倒 U）。短板：ON 无理论根据（同时奖励"远离过去+贴近未来"，实为预测热点）；生成/评测共享同一 embedding 空间的自证循环；代码审计发现"固定团队规模"被字符串匹配邀请机制破坏、择优有拼写 bug、HD/CD/CI 全套评测代码未发布。

⑥ 评估件 · Tree-of-Debate

Evaluation, not Generation

前七篇都在「产 idea」，但"两个候选谁更新颖"这件事全线都靠 LLM 一句话打分。Tree-of-Debate（ACL 2025 Main）把这个判断做成一棵可检查的辩论树 —— 它是给上面所有系统补的评估环节。

6.1Tree-of-Debate · 树形即结论

论文对 p₁, p₂ + 根话题 n₀70/100 对互不引用、跨社区
→
实例化为两个辩手 persona辩题="p₁ 对 nᵢ 的贡献比 p₂ 更好"
（辩"更新颖"反而更表面）
→
每节点三阶段① Self-Deliberation：各自检索 top-δ 段落提贡献声明 + preempt 备弹药
② Debate：present → respond → revise
③ 主持人判扩展：(推进∨有疑问)∧无赢家 → 再裂一层
→
辩论树 + 主持人综合总结树形即结论：重叠想法辩出长子树，独有想法迅速封叶
先讲相似、重点讲差异

结果：Contextualization 95.21 vs 最强基线 75.57（+26%）；消融证明"结构负责语境化、检索负责事实性"。对 idea 生成线的意义：CoI 的 Arena 对战、SciPIP 的成对比较、VirSci 的查新投票，都可以换成/接上这棵辩论树 —— 判断过程从黑箱打分变成可追溯的论证结构。短板：标注者=评测者；基线全是裸 prompt（增益来自辩论还是更长输出分不清）；树深控制与论文不符。

⑧ 共同软肋（也是留给我们的空位）

Shared Weaknesses
1 · 评价协议同源。生成器和裁判共用同一个 LLM/embedding 空间（ResearchAgent 的 LLM 评 LLM、VirSci 的自证循环、CycleResearcher 的自己人打分）。Tree-of-Debate 是目前唯一把"判断"做成可追溯结构的尝试。
2 · 无下游执行验证。八篇没有一篇回答"idea 被执行后是否成立"。Feasibility 是 CoI 评测里所有自动方法的共同瓶颈；CycleResearcher 干脆把实验结果编出来仍拿高分 —— 这恰好是 AutoSci 端到端闭环的天然切入点。
3 · 结构增益拆不干净。ResearchAgent 随机材料也涨分、Deep Ideation 无图消融、SciPIP 被批"与 SciMON 差距边际"—— "结构化 RAG"的贡献天花板是 ICLR 评审的共识判词。
4 · 三种新颖性哲学互不包含。事后查重（CoI/SciMON）× 事前分工（SciPIP）× 事中打分（DeepIdeation/ResearchAgent）从未同台；再叠上 VirSci 的时间对照库与 ToD 的辩论树评估 —— 组合空间是全空的（见 §2.1 地图的空白象限）。
