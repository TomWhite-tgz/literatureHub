PaperPilot 深读评价（2026-08-02）

分类：包装的好看（工程外壳真实，科学内核虚——三大论文卖点在代码层面全部失守）。

  • 论文：arXiv:2607.00597v2
  • 深读方式：论文全文 + 核心代码路径（27,492 行 Python 中的方法核心 ~7.9k 行 + plot/eval 脚本）

三大卖点逐一失守

1. "工作流归纳 (workflow induction)" 实为模板抄写

  • DAG 由 LLM 一次 complete_json 调用直接产出（core/agents/symbolic_agent/runtime/agent.py:151-296），无搜索/程序合成/学习过程。
  • System prompt 明确要求 "mirroring the reference DAG below for this direction"（runtime/agent_prompt.py:97-107）；参考对象是 references/ 下 36 份人工迭代调优的 JSON 模板（meta 带十几轮手工调参记号）。
  • 多轮"自发分阶段行为"（论文 Fig.3）相当程度是 prompt 硬约束的产物（"FIRST ask MUST be about year range"、min_turns/min_asks 门控强制不许提前 finalize）。

2. "偏好优化"训练代码 0 行

  • 论文声称 5,540 条 SFT + 1,733 偏好对 + IPO 式 DPO（附录 C.6 给了超参）；training/ 只有 coming soon README，全库 grep 不到任何相关代码。评测 runner (run_eval.py)、用户模拟器、leak-checker 同样缺失；评测数据 "distribute on request"。

3. 主表数字三重硬伤

  • 两行 baseline 被外置 JSON 覆盖：plot/0509_multimodel/build_main_table.py:90-109 交代——本地 v8 框架重跑 Qwen3.5-397B(Workflow) 两行 Hit@1 都只有 17.0，论文用的是 v6 框架的 40.0/57.0，且 "We do not have the v6 trajectories locally"。同配置换框架版本结果崩一半 → 整表可信度存疑；Figure 4"多轮精炼提升"最大涨幅恰是这对不可复现数字。
  • 旗舰 PaperPilot-9B 行是硬编码的（build_main_table.py:16-18,83-88，raw trajectory not locally available），且 forced_finalize = 99.5%（199/200 case 被强制终局），代码注释称 "intentional artifact, ignored per project convention"，论文只报 "err 9.5%→0%" 未披露强转机制。
  • 成本 19 倍改写：实录 $0.343/case 以 "cost_tracker fallback-price bug" 为由改成 $0.018（plot_paper_figures.py:126-130，上文还留着 "TODO confirm" 占位）；论文"比 DeepResearch 便宜两个数量级"建立在此之上。

其他

  • 与 PaSa 没有任何实验比较（仅出现在勾叉表）；评测集自建 200-case；检索配额不对齐（自己每 case 从 S2 免费拉 4千-1万篇候选，成本只算 agent token）。
  • operator 数量三处口径不一：论文 17 / 代码 ~25 / README "~50"。
  • 27.5k 行构成：方法核心 ~7.9k（其中 ~2k 是 prompt 文本），api/ui/clients/observability/plot 等工程外壳约 2/3。

唯一真实的亮点

结构化 DAG 编辑机制是真实现（非重新 prompt）：modify_dag 输出操作列表（replace_node/add_node/set_param...），apply_operations() 深拷贝原子应用（runtime/planner.py:103-161）+ 结构/枚举校验器 + 失败带错误信号重试。加上拓扑排序并行执行器和 ~25 个类型化 operator，约 5k 行是体面的可跑工程——四篇中唯一真正的"多轮反馈结构化修改"实现。
