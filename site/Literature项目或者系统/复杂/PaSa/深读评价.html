PaSa 深读评价（2026-08-02）

分类：复杂（真材实料），四篇文献搜索系统（PaSa/PaSaMaster/PaperPilot/PaperScout）中唯一经得起深读的。SOTA 数字建议打七折看。

  • 论文：arXiv:2501.10120v2，ACL 2025 Main，ByteDance Seed
  • 深读方式：论文全文 + 全部开源代码（~1000 行）逐文件审读

真的部分

  • Eq.3 session 级 PPO 是真算法贡献：轨迹长达数百篇论文放不进上下文，以 [Stop] 切分 session，跨 session 用折扣价值估计 V̂(S_{q+p_j}) 回传 credit——针对"动作产生新任务项"结构的干净设计。
  • Selector 决策 token 前置、兼任 Crawler RL 训练的单 token reward model，是聪明的工程复用。
  • 从顶会 Related Work 反向合成 35k query-paper 对（AutoScholarQuery）是低成本高质量的数据方案。
  • 训练真实（SFT + PPO，16×H100），7B 权重、数据集全部开放在 HuggingFace；README 训练超参与论文 Table 12 一致。
  • 消融较充分（w/o Expand / w/o RL / w/o Selector-as-RM、α 扫描、动作成本扫描）。

要打折的部分

  1. 部署形态是硬编码流水线，非论文渲染的自主 agent：paper_agent.py:207-221 固定 2 层 expand、每层按 Selector 分取 top-20，[Stop] 从不用于宏观终止——训练时是 MDP，推理时是 pipeline。
  2. benchmark 结构性自利：GT 来自顶会引文（citation 可达），恰是 [Expand] 动作优势区（w/o Expand recall 掉 22.98% 印证同构）；RealScholarQuery 候选池由"PaSa+baselines 检索并集"构成，深爬独有发现的份额由 PaSa 自己定义。
  3. 成本不对等且不报：每 query 平均 382 个动作 vs Google 单次查询，延迟/成本全文缺席。
  4. arXiv-only 硬限制未列入 Limitations：全部检索以 arxiv_id 为主键（utils.py:38-75）。
  5. 真 bug：run_paper_agent.py:56 把 expand_papers(20) 传给了 search_queries(应为5)；ar5iv 引文解析不可靠（utils.py:250 作者自带 warning），是 [Expand] 单点故障。
  6. 代码只含推理+评测；SFT/PPO 训练在 fork 的 trl/transformers 仓库，数据构建代码未开源。

与其他三篇的关系

后三篇（PaSaMaster/PaperPilot/PaperScout）实质都活在 PaSa 的问题设定和评测生态里（benchmark、reward model、baseline），但没有一篇与 PaSa 做了公平正面比较。
