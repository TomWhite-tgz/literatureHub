因此，Git 的“50 万行新增”不能直接理解为团队新写了 50 万行核心编排逻辑。大量体积来自嵌入的 Deep Research/CAMEL 代码和任务仓库。真正重要的是下面这些结构变化。

01 · 多模式入口

从 discovery 单入口到统一路由

launch.py 在 QA 与 discovery 间转发；launch_qa.py 直接进入 DR；discovery 还可区分 experiment / report。

02 · 长期记忆

研究经验开始跨轮次积累

新增 task_memory.py、online_memory.py、long_memory.py、retriever 和离线导入脚本，支持失败方向过滤、IdeaGraph 与 prompt evolution。

03 · Deep Research

不再只是 Survey Agent

新增 DRAgent 和独立 FlowSearch 图工作流，负责问题分解、并行检索、网页/学术源调用与答案/报告合成。

04 · 验证与搜索

实验循环变成长程优化

新增 fresh / incremental loop、resume、MCTS、GPU allocator、并行实验、最佳结果回填和独立 ReportWriter。

05 · 论文复现

加入另一类任务契约

通过 sci_tasks 子模块接入 ResearchClawBench；把 task_info.json + checklist.json 转为任务，生成代码、图表和报告，再将评分反馈给下一轮。

06 · 工具协议

从固定函数扩展为 ToolRegistry + MCP

加入 MCP manager、远程/本地科研工具、搜索工具和统一注册表，工具接入不再完全写死在 Agent 内。

07 · 执行后端

Aider 被替换

1.0 的 experiments_utils_aider.py 被删除；1.5 加入 Claude Code、iFlow 及其 MCTS 变体。OpenHands 仍出现在参数和 dispatch 中，但对应方法缺失，属于未闭合路径。

08 · Agent 角色

8 个注册角色增加到 11 个

在 1.0 的 generation/reflection/evolution 等角色上，增加 DR、experience、prompt evolver；另有 codeview 与 experiment analysis 旁路组件。

ResearchClawBench 的接入：做了什么，又不能说明什么？

最准确的表述是：InternAgent 把外部 benchmark 接成了一个 benchmark-driven 论文复现环境，而不是仅仅下载了一批任务，也不是已经取得正式榜单成绩。

层面源码中已确认的事实应如何理解
接入方式sci_tasks 是 Git 子模块，固定到 ResearchClawBench 提交 9b5288e；评分代码通过符号链接复用官方实现。任务与 rubric 有明确外部版本，不是 InternAgent 自己临时拼出的案例。
运行方式识别 task_info.json，将任务、数据清单和 checklist 转成 InternAgent prompt；默认示例由 Claude Code 编写与迭代实验。InternAgent 提供外层研究与优化循环，具体代码执行仍依赖 coding-agent 后端。
评分闭环报告按 checklist 逐项打分并写入 final_info.json；得分和薄弱项会进入下一轮提示。benchmark 不只是事后测量，也成为系统搜索时使用的外部奖励信号。
证据状态主仓库没有随附 InternAgent 的 40 任务完整结果，ResearchClawBench 的 agent preset 中也没有 InternAgent。“已接入”不等于“已完成正式评测”或“已经上榜”。
与论文关系1.5 报告于 2 月发布且没有提到 ResearchClawBench；接入代码在 5 月 7 日才公开。这是 1.5 发布后的工程扩展，不能倒推为论文原始实验贡献。
最重要的评测边界：ResearchClawBench 官方执行阶段只给 Agent 任务说明、数据和相关文献，目标论文与 checklist 留给评分器；InternAgent 的适配则把 target_study/ 链接进工作区，并把 checklist 摘要直接写入任务约束，之后还根据逐项得分继续优化。因此它更像“论文复现训练场 / 开发环境”，结果不能未经控制就与官方盲测榜单横向比较。
它真正意味着什么：InternAgent 的任务边界从“在已有代码库上优化算法指标”扩展到“从科研问题和原始数据出发，生成分析代码、图表与研究报告”；但其价值目前主要是能力接口和闭环机制，而不是一份已经验证完毕的 benchmark 成绩单。

什么变了，什么其实一直没变？

持续不变的主轴

Idea → Experiment → Feedback

  • 从 Dolphin 到 1.5，都围绕“提出方向、改代码、跑实验、根据结果继续”的闭环。
  • Survey / literature 的作用始终是给 idea 和方法提供外部知识。
  • 任务指标或实验结果仍是最强的外部反馈信号。
真正发生的升级

控制器从单次脚本变成持久平台

  • 1.0：角色化、状态化、配置化。
  • 1.5：跨轮次记忆、多种任务契约、多入口、多工具协议和可恢复执行。
  • 最新：主要扩大模型接入面，没有再次改变控制结构。
最准确的理解：InternAgent 的演化不是“每一版都重写科学方法”，而是逐步把一次性的自动实验脚本，包装成能够持续运行、积累经验、调用更多工具，并支持更多科研任务形态的控制系统。
