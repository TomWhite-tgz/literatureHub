Deep Ideation — OpenReview 讨论存档

来源: OpenReview, ICLR 2026 Submission #20167（存档日期 2026-08-04，OpenReview API 有反爬验证，本文为人工抓取全文整理）
标题: Deep Ideation: Designing LLM Agents to Generate Novel Research Ideas on Scientific Concept Network
作者: Keyu Zhao, Weiquan Lin, Qirui Zheng, Fengli Xu, Yong Li（清华 FIB Lab 系）
结果: ❌ Withdrawn（2025-11-27 作者撤稿；评分 2 / 6 / 2 / 2，作者未做 rebuttal）
arXiv: 2511.02238 · 代码: https://github.com/kyZhao-1/Deep-Ideation（截至存档日仅 README 占位，代码未放出）

摘要（要点）

已有 idea 生成方法要么简单 prompt LLM，要么只用关键词共现/语义相似度做文献统计关联，忽略科学概念间复杂的上下文关系。Deep Ideation 框架：①从 10 个 AI 顶会约 10 万篇论文构建科学概念网络（关键词共现 + 上下文关系）；②explore–expand–evolve 工作流迭代精炼 idea，用 Idea Stack 追踪研究进展；③用真实评审反馈训练的 critic engine 对 novelty/feasibility 给持续信号。声称比基线整体提升 10.67%，生成 idea 超过顶会接收线。

Keywords: Large Language Model, LLM Agent, Automated Scientific Discovery, AI Scientist

Review 1 — Reviewer gb37（Rating 2, Confidence 4; Soundness 2, Presentation 3, Contribution 2）

Summary: 概念网络（100k 论文）+ explore-expand-evolve 循环 + 基于 peer review 训练的 Critic（novelty/feasibility 1-5 分）；4 个 AI 领域对比 SciMON、ResearchAgent、MOOSE-Chem 等，报告 8-10% 提升。

Strengths: 方向重要；语料大、模块化设计清晰；图 1-2 可读性好；4 领域一致的实验报告与结构化打分 rubric；有 critic 消融。

Weaknesses:
- 类似概念网络与迭代 ideation 已存在，方法新颖性偏增量式。
- Critic 是在 LLM 生成的 paper–review 对上训练的，不是真实人类评审；消融提升仅 3-5% 且只有 LLM judge 衡量，无相关性/可靠性分析；数据污染与模型 checkpoint 日期不明。
- 数据集统计未报告。
- novelty/feasibility 用自造 rubric，无同行评审标准参照；可能把 novelty 与图距离混同；缺 Si et al. 2024 提出的 Effectiveness 维度。
- 提升幅度小可能在方差范围内；人类评估细节严重缺失（盲法？招募？专业？统计显著性？用的哪个数据集？）。
- 100k 语料对 ideation 的实际价值不清：只用关键词共现+LLM 生成的短上下文关系，机制简单，缺深层概念/因果理解；聚合函数 g(·) 未定义；没有分析图对 novelty/feasibility 的实际贡献。
- 对比部分不公平（MOOSE-Chem 是化学领域）；缺多智能体基线（Many Heads、ResearchTown、IdeaSynth/WebWeaver/LDC）。

Questions: 数据分布？relation(vi,vj,p) 怎么算（LLM 解析还是 embedding 相似度）？critic 用真实数值评分还是仅文本理由微调？如何保证生成 idea 不是对 checkpoint 后所见论文的换皮？

Review 2 — Reviewer DTQ4（Rating 6, Confidence 5; Soundness 4, Presentation 4, Contribution 4）

Strengths: 概念网络包含上下文关系，比统计方法更有依据；explore-expand-evolve + Idea Stack 模拟人类研究者认知过程；真实评审反馈训练的 Critic 使迭代不"盲目"。

Weaknesses: 边特征（上下文关系）的形式化定义太高层——如何表示、量化、蒸馏成 LLM 可稳健查询的形式不明；Critic 只用 4278 条样例微调，跨 4 个领域的泛化存疑。

Questions: 能否给"复杂上下文边特征 vs 简单边特征（共现频次/连接文本 embedding）"的对照实验？每个 idea 的摊销成本（token/API/时间）对比 one-shot 或更简单的迭代基线？

Review 3 — Reviewer Dots（Rating 2, Confidence 4; Soundness 3, Presentation 2, Contribution 2）

Strengths: 100k 语料；发布了基于真实评审反馈的 review 数据集；有消融、案例研究、SOTA 基线、人类+自动双评估。

Weaknesses: 为什么用共现概念图而不用科学 IE 系统抽取关键词与关系？框架似乎纯靠 prompting；邻居关键词的思路 ResearchAgent 和 SciMON 已提出；建议加入领域 LLM（如 OLMO2）。方法节 evolve 部分很混乱（确切算法？关键词何时删除？与 ResearchAgent/SciMON 的迭代精炼区别？）；评估数据集是什么？100k 全用于评估吗？4.2 节评价指标？人类标注者背景与一致性？缺 use of LLMs 声明、缺代码、缺伦理声明。

Review 4 — Reviewer hrL1（Rating 2, Confidence 4; Soundness 2, Presentation 2, Contribution 2）

Strengths: 超越静态关键词/embedding 检索，动态检索组合概念关系；用真实评审文本微调给出现实反馈信号；概念网络与数据集若发布对 AI4Science 有用。

Weaknesses: 未分析训练语料/评审数据/参照论文与 LLM 训练截止日期的先后（公平性与新颖性判断的关键）；4.2.2 节列了 54 位研究者却没有遴选标准/专业/校准细节；无人类评审者间一致性、无不同 LLM judge 间一致性；只消融了 Evolve 和 Critic；附录 A.1.3 与 A.1.7 的 prompt 基本重复（编辑疏漏）。

Questions: 边特征 F_ij 如何从多篇论文具体计算？训练/评估数据是否晚于 LLM 截止日期？54 位评估者如何选出、与 LLM 评分一致性？GPT-4o vs Gemini 2.5 Flash 等 judge 间一致性？计算成本与可扩展性？Evolve 阶段停止准则？

Withdrawal（2025-11-27）

作者确认撤稿（无 rebuttal、无回复）。

归档者备注

  • 评分 2/6/2/2，撤稿。三个 2 分的共同指向：概念网络的机制价值没有被论证（共现+LLM 短摘要 ≈ 换皮的 RAG）、Critic 训练数据可疑（gb37 直指是 LLM 生成的 paper-review 对而非真实评审）、人类评估（54 人）细节几乎为零。
  • 对本档案的价值：①"概念网络/知识图谱做文献组织"路线的失败样本，与 CoI 的"链式组织"、ResearchAgent 的"实体共现知识库"构成对照；②评审们点名的基线清单（SciMON、MOOSE-Chem、ResearchTown、IdeaSynth 等）本身就是 idea 生成领域的文献地图；③代码未放出+撤稿，可信度档位偏低，精读时以论文声明为主、无法做代码审计。
