Deep Ideation

本质：关键词共现图上的游走式 RAG——每轮从图里挑一个新关键词塞进 prompt，让 GPT-4o-mini 重写一版 idea，再由一个微调过的打分器决定继续还是换词

Keyu Zhao · Weiquan Lin · Qirui Zheng · Fengli Xu · Yong Li
清华大学 FIB Lab 系 · ICLR 2026 Submission #20167 · GitHub: kyZhao-1/Deep-Ideation

论文 PDF（本地） arXiv 页面 OpenReview 评审存档（本地） 官方 GitHub（空仓库）

一句话本质

剥掉「科学概念网络」「explore–expand–evolve」这些包装，这个系统就是：先把 10.7 万篇顶会论文压成一张关键词共现图（边上附一段 LLM 写的短文本），然后让 LLM 在图上一步步"捡词"——每捡一个新词就重写一版 research idea，由一个 8B 小模型打分决定要不要继续。没有新模型、没有图算法，全程是 prompt 工程；唯一训练过的组件是那个打分器（critic），而它的训练标签也是 LLM 转写出来的。

下面这张「论文术语 → 实际是什么」对照表，是读懂全文的钥匙：

论文里的说法拆开之后实际是什么
科学概念网络（scientific concept network）关键词共现图：LLM 从每篇论文抽 3–4 个关键词当节点；同一篇里一起出现的词连一条边；边上挂一段 LLM 写的 2–4 句话（"这篇论文是怎么把这两个词联系起来的"）。没有关系类型、方向、权重，也没做实体消歧
explore查图：取当前关键词的邻居，把边上那段文本读出来
expand加词：让 LLM 从邻居里挑一个新词加进关键词集，然后把整个词集重写成一版 idea proposal
evolve换词或重写：词集满 4 个之后，由一个 prompt（Router）判断"是词不行还是写得不行"，对应换掉一个词或重写文案
Idea Stack一份越攒越长的对话历史：每轮的词集、proposal、分数全部原样塞进下一轮 prompt，没有检索也没有压缩
Critic Engine（"用真实评审反馈训练"）LoRA 微调的 Qwen3-8B，给 idea 打 novelty / feasibility 各 1–5 分。训练数据只有 4278 条，且标签是 GPT 从 OpenReview 论文+评审里转写出来的（详见 ④），"真实评审"只是最上游的原料

⚠ 可信度前提：代码未放出，无法做代码审计。官方仓库截至 2026-08 只有一个 README；论文承诺公开的概念网络数据集与 4278 条训练数据也都没发布。本页所有实现细节只能来自论文自述（论文声称）或推断（合理推断），全部数字无法独立复现——评审也点名了这一点。

① 跟着例子跑一遍 ② 和同类系统比，它新在哪 ③ 评审关心的三件事 ④ 为什么 2/6/2/2 撤稿

① 跟着一个例子把系统跑一遍

假设用户输入初始关键词 Model Editing，想要一个新 idea。系统会这样运转（机制全部来自论文 §2–3 与附录 prompt，论文声称）：

第 1 步 · 查图（explore）

在共现图里找到 Model Editing 的邻居（最多取 12 个，这是调参出来的最优值），比如 Large Language Model、Knowledge Neurons……并把每条边上那段"某某论文如何联系这两个词"的 LLM 短文本一起取出来。

第 2 步 · 挑一个词加进来（expand）

把候选词、边上的文本、每个词到当前词集的最短路长度，连同全部历史（Idea Stack）一起塞给 GPT-4o-mini，让它挑恰好一个新词。挑词规则写死在 prompt 里：嫌不够新颖就挑图上距离远的词，嫌不可行就挑距离近的词——注意，"novelty=图距离"是系统的显式设计，这一点后面评审会追杀。

第 3 步 · 重写 idea + 打分

用新词集写一版三段式 proposal（背景 / idea / 大致实现路径），交给 critic（微调的 Qwen3-8B）打 novelty、feasibility 各 1–5 分。词集、proposal、分数全部压进 Idea Stack。

第 4 步 · 词满 4 个后，换词或重写（evolve）

词集到达上限 4 后，一个叫 Router 的 prompt 看分数决定：分低是词的问题 → 换掉一个词（用户给的初始词不能动）；词没问题是写得差 → 重写 proposal。然后回到第 1 步继续。

第 5 步 · 什么时候停？——论文没说

流程图里画了个 "Stop Triggering"，正文说"达到满意水平或满足停止准则"就停，但满意阈值是多少、最多跑几轮、由谁判停，全文包括附录没有任何一处定义。评审 hrL1 直接问了，作者没有回答。核对发现

一个此刻就能看出的裂缝：边特征 Fij 号称是"聚合多篇论文中两词的关系"，公式里写了个聚合函数 g(·)——但 g 在正文两处的定义都是同义反复（"a function that aggregates the relationships"），附录只给了单篇论文的关系提取 prompt，跨论文怎么聚合连 prompt 都没有。两个评审（gb37、hrL1）都抓到了这一点。核对发现

② 和同类系统比，它到底新在哪

idea 生成的核心问题都是一个：给 LLM 喂什么结构的文献，它才能产出有据可依的 idea？三个代表系统给了三种答案：

系统文献被组织成什么一句话点评
Chain-of-Ideas 沿引用关系排成的论文链（保留时间脉络） 关系语义最明确（引用=承继），但只有单条脉络
ResearchAgent 实体共现统计库（entity linking 后计数） 无语义但客观可验证；"取邻居实体扩展 idea"的思路就是它先提的
Deep Ideation（本文） 关键词共现图，边上挂 LLM 写的自由文本 语义最丰富、也最不可验证；检索从"一次性"变成"逐步游走"

照这个对比，本文相对前人的真增量只有两点：

  • 边上的 LLM 文本——比纯共现计数多了"这两个词是怎么被联系起来的"这层语义；
  • 游走式检索——不是一次检索完就写，而是每轮按图距离挑词、逐步逼近。

致命的一点：这两个增量，论文一个都没验证

消融实验只做了"去掉 evolve"和"去掉 critic"两项；概念网络本身、边上的文本、图游走策略，从头到尾没有被单独验证过。唯一给 6 分的评审 DTQ4 点名索要"复杂边特征 vs 简单共现计数"的对照实验——不存在。所以严格地说：你无法区分这套系统的产出质量来自那张图，还是来自图背后那个本来就很强的 GPT-4o-mini。这就是"与换皮 RAG 不可区分"的确切含义。

③ 评审关心的三件事（以及核对下来谁对谁错）

四份评审 2 / 6 / 2 / 2，作者一个字没答辩，直接撤稿。十几条意见看似零散，其实归拢起来评审只关心三件事——恰好对应这篇论文的三层结构：卖点、组件、证据。每件事我们都拿 tex 原文核对过。

关心点一：你的核心卖点（概念网络），到底有没有用？

评审怎么说：gb37（2 分）："网络只用了关键词共现和 LLM 生成的短上下文，机制简单，没有分析图对 novelty/feasibility 的实际贡献；聚合函数 g 未定义。" DTQ4（6 分）也索要边特征的对照实验。

核对结果：完全成立。g(·) 两处定义都是同义反复、跨论文聚合无任何实现描述（见 ①）；边文本 vs 共现计数无对照；概念网络无消融。更糟的是，评审 gb37 怀疑"novelty 可能与图距离混同"，核对发现这比他说的更严重——挑词 prompt 明写"要 novelty 就选最短路长的词"，混同不是隐性偏差，是显式设计。核对发现

关心点二：critic 号称"用真实评审反馈训练"，是真的吗？

评审怎么说：gb37 指控 critic 训练的是"LLM 生成的 paper–review 对"，不是真实人类评审；DTQ4 质疑 4278 条样本撑不起跨领域泛化。

核对结果：指控实质成立，且论文构成过度声称。OpenReview 的真实评审里根本没有 novelty/feasibility 的 1–5 分（只有 rating/soundness），这些数值标签是 GPT 从"论文+评审"里转写出来的，转写规则全文未说明；训练目标里的推理链，§3.4 自己承认是 "simulated reasoning"。也就是说 critic 实际学的监督信号——分数、描述、推理链——全部是 LLM 产物，真实评审只是流水线最上游的原料。摘要里 "trained on real-world reviewer feedback" 的说法是拔高。核对发现

关心点三：你的评估数字，能信吗？

评审怎么说：三个 2 分共同点名——人类评估没有招募标准/盲法/一致性/显著性（gb37、hrL1、Dots）；LLM judge 之间的一致性没报告（hrL1）；提升幅度可能就在方差范围内（gb37）；评估用了什么数据集、每个方法评了多少条 idea 都没说（Dots）；训练语料和 LLM 截止日期的污染关系没分析（gb37、hrL1）。

核对结果：全部成立，一项都没冤枉。附录 A.6 关于人类评估确实只有三句话。此外还有一层评审没有明说的结构性问题：系统内环用 critic 按 novelty/feasibility 优化，外环再用 5 个 LLM 按几乎同一套 rubric 打分——等于对着考题练习再参加考试，而基线没有这层内环。合理推断

本页独立发现（评审没抓到）：主结果表数字自相矛盾。核对发现

  • SciMON 的 CV 列：Nov 2.50、Fea 3.02，平均却写 3.76（应为 2.76）；NLP 列平均写 3.24（应为 3.48）。而 Improvement 行恰好是按修正值算的——说明作者手里有对的数据，表是誊错的。
  • ResearchAgent 的 Overall Fea 3.47 与它四个分域的均值 3.27 对不上，而全文 headline 的"提升 10.25%"正是拿这个 3.47 当分母。
  • 摘要说提升 10.67%，正文和表格说 10.25%，无解释。
  • 介绍里"达到 8/10 个顶会的接收线"没有任何分会议数据支撑，且 NLP 域 3.81 < 接收论文 3.83，自己就与这句话矛盾。

顺带一句："超过顶会接收论文"这个 headline 应该怎么读？那条"Accepted Papers"基线，是把真论文的标题/摘要/引言让 LLM 重新转写成 proposal 格式再打分。所以更合理的解读不是"系统超越了人类科研"，而是：这套 rubric 偏好为它量身生成的文本，真论文经二次转写反而失分。

④ 为什么 2/6/2/2 撤稿：三成怪 idea，七成怪执行

Idea 层面（约三成责任）

方向本身不坏——给共现图的边补上语义、把一次性检索改成逐步游走、用微调 critic 替代裸 prompt 评审，这些都言之成理，6 分评审 DTQ4 认可的正是这些。但这个 idea 的增量空间天生就窄：邻居扩展、迭代评审、图谱假设生成全都有先例，留给它的只有两个可辩护点。

执行层面（约七成责任）

恰恰这两个可辩护点全都没给证据：g 没定义、边文本没对照、网络没消融。再叠加 critic 数据的过度声称、人类评估三句话交差、主表数字自相矛盾、承诺开源全部没兑现。这不是方向错了，是验证纪律和写作纪律的全面缺失。零 rebuttal 直接撤稿，与其说被冤枉，不如说自知证据链撑不住。

对本档案（idea 生成系统怎么做文献）的启示

概念网络这条路选择了语义最丰富、也最不可验证的文献表示——而验证恰恰是这篇论文没做的事。如果不能证明图结构本身（而不是背后那个本来就很强的 LLM）贡献了产出质量，它与换皮 RAG 不可区分。以后读同路线论文，直接用三连筛查：①边特征有没有对照消融？②迭代有没有判停准则？③评估 judge 和内环 critic 是不是同源？三问皆空的，大概率是又一个 Deep Ideation。
