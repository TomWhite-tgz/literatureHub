Bottom line

不是“空气团队”，但 AI4AI 的最大叙事尚未被完整公开证据闭合。

我的判断是：人、模型、数据样本和工程代码都是真实的，并且与 Microsoft Research Asia 的 R&D-Agent 系列工作存在非常清楚的人员与技术延续。Aquila 的搜索运行时也不是 PPT：上下文状态、回滚、压缩、工具、日志、评测与 SFT 导出都有代码和测试。

但“数百个 AI worker 在两个月内自动改进整个 AI 系统”的核心过程，目前主要来自团队自述。公开仓库没有交付完整的多 Agent 优化控制器、私有开发集、门控历史、全部 intervention records 或端到端成本账单。因此可以相信他们做出了强搜索 Agent，不宜把报告直接解读成已经验证了通用的自动 AI 研发工厂。

04

具体怎么实现：概念闭环与公开系统逐层对照

AI4AI 不是一个新优化器，而是一套“允许 Agent 在受限范围内改 AI 系统、由隔离评测器验收”的研发流程。Aquila 是这个流程的 Deep Search 案例。

报告描述的 bounded-exploration loop

1. 人定义 Contract目标、私有开发集、允许改动、预算、风险、验收规则
2. Agent 诊断从失败切片、轨迹和指标找瓶颈
3. 提交 Candidate改数据、SFT、runtime、context、工具或基础设施
4. 隔离 Evaluator隐藏标签不暴露；每个 candidate 一次 gate 查询
5. 接受 / 拒绝按预注册规则决定是否进入下一版本
6. 共享经验成功和失败都连同 provenance 写入 memory
设计意图很合理：它试图避免 Agent 直接看到隐藏答案、无限试探测试集或自我批准变更。真正的科学问题是：这套治理层运行了多少轮、哪些变更是谁提出的、各模块的边际贡献有多大——公开材料尚不足以重建。

Graph-grounded synthesis

先构造“必须通过工具才能找到”的问题

报告称其从可验证网页证据构造 evidence graph，再由图中跨页面实体/关系生成问题；随后混淆直达锚点，并做答案唯一性、工具可达性与 shortcut 检查。目标是减少单页复制、训练集背诵和不可验证题。

公开了什么：Hugging Face 上有 7,000 条双语多轮搜索轨迹（5,000 英文、2,000 中文），2.75 GB，Apache-2.0；但这是“更大 SFT 语料的样本”，不是完整训练集。少量 QA 内容来自 OpenSeeker-v1-Data。

Train what the model actually saw

完整日志不等于训练时可见上下文

长搜索轨迹会经历压缩、回滚、丢弃和工具失败。做 SFT 时，他们不是简单把完整 audit log 拼成对话，而是重放 marker，重建每一步模型当时真正看见的状态，再对合格的 assistant turn 计算 loss。

轨迹中位数
102.7K完整日志 token
工具调用中位数
72p90 = 176
超长轨迹
5.5%完整日志 > 256K，但单次可见状态 ≤ 256K

训练使用 256K packing；mini/pro 学习率分别 2e-5 / 1e-5，Adam β=(0.9, 0.98)，weight decay 0.1，per-token loss。

Two representations

不可变审计日志 + 动态可见状态

ConversationRuntime 持有 append-only trace。压缩、回滚和 discard 不破坏旧记录，而是追加 marker；重放 marker 可以重建模型在某个 turn 看到的精确上下文。这个设计同时服务故障诊断、可复现评测与 SFT 导出。

YAML config → recipe runner → TaskOrchestrator ↙ model client ↘ ToolManager OpenAI-compatible search / scrape / Python ↓ append-only task trace ↙ ↘ evaluator/dashboard state-faithful SFT export
Important separation

AxisRL 是真框架；但 Aquila 最终版不是 RL 成果

AxisRL 公开了 agentic RL 的系统层：rollout、trainer、权重同步、数据句柄、partial rollout、PPO/GRPO 系列、MoE routing replay 和故障重放。PBSD 则提出利用“知道正确答案的 privileged teacher”与普通 student 的 likelihood ratio，将最终答案证据分解成 turn-level 权重。

然而 Aquila 报告明确写道：answer-conditioned process-reward 方案只通过低成本筛选，没有完成完整 RL training + gate，因此没有进入 mini/pro 发布版。不能把 PBSD 或 AxisRL 自动算作 Aquila benchmark 成绩的因果来源。

What is solid

同尺度表现很强

按报告表格，mini 在 <40B open-weight 组七列均第一；pro 在 <400B open-weight 组已列的六列均第一。模型与 harness 都能获取，具备复测基础。

What is mixed

不是统一擂台

只有标 † 的一部分 baseline 在共同 harness 中复现；其余来自不同公开报告、工具、judge 与日期。Live web 还会随时间变化。

What is missing

缺少不确定性与代价

没有完整多次运行误差条、开发算力、推理时延、搜索/API 成本、evaluator 成本和人工审核时长。

如何正确阅读“第一名”

它支持的较窄结论是：在团队定义的协议和公开比较表里，Aquila 的参数—性能前沿很有竞争力。它不支持“通用最强 Agent”，也不能证明 AI4AI 闭环的每个组件都有效。报告自己也承认没有做完整因果分解，后期改动可能依赖早期改动，简单 ablation 未必足够。

最有价值的复测应固定：模型 checkpoint、prompt/date、搜索供应商、网页快照、judge、并发与 retry 规则，并同时报告 Pass@1、总工具调用、token、墙钟时间和美元成本。

靠谱吗？按三种不同问题回答

“团队真实”“模型很强”“AI4AI 已被证明”是三个不同判断，不能合并成一个 yes/no。

Assessment

综合判断：值得认真跟踪，暂不宜照单全收

  • 人员可信：核心作者有 MSRA / SJTU 可追溯履历，前序论文和代码连续。
  • 工程可信：公开代码不只是 README，有 runtime、工具、状态重放、评测、测试与训练 recipes。
  • 开放程度较高：两个模型开放权重，7k 轨迹样本及 Apache-2.0 框架可下载。
  • 成绩需复测：benchmark 对照混合来源，搜索环境和 judge 具有时间依赖。
  • 过程证据不足：缺少完整 intervention ledger、私有 gate 历史与端到端消融。
  • 组织透明度弱：法人、资金、算力、核心成员结构均未明确披露。
  • “AI 自动研发规模”未独立验证：300+ workers 与千卡等效属于团队自述。
高“他们是否真的有能力做系统？”

R&D-Agent → FT / RL → Search 的研究路径与开源工程互相印证。

中“这些 benchmark 数字是否可靠？”

数字有报告、配置和权重支撑，但仍需独立、同 harness、多次运行复现。

低—中“AI4AI 是否已被证明可通用规模化？”

当前是一个 Deep Search case study；核心自动优化过程、成本与跨域迁移尚未被公开验证。

我会怎么验证下一步：先用同一份冻结网页语料在 BrowseComp / BrowseComp-ZH 上复跑 50–100 题；再把 Aquila checkpoint 与一个同底座 Qwen 模型置于完全相同的 AxisAgentic 配置中，报告准确率、工具调用、token、时间和失败类型。若团队能再公开候选 intervention 的接受/拒绝日志及统一成本账单，AI4AI 的核心主张会显著增强。
