先回答你最关心的问题

作者是否统一实现系统，再放进 Benchmark 实测？

不是。 论文确实列举并整理了大量 系统、Benchmark 与 verifier；但作者统一的是证据抽取和分类编码规则，不是系统实现、运行环境或实验预算。它没有把 56 个系统重写到同一代码库，也没有让这些系统在同一组 Benchmark 上重新跑一遍。

方法判定：它统一了什么，没有统一什么

最容易误读的地方是论文同时有“系统矩阵”和“Benchmark 表格”。这些表格让对象看起来被放在同一个实验框架里，但它们实际上是文献编码表，不是作者运行系统后得到的 leaderboard。

这篇论文究竟在做什么

它是一篇面向“科学可辩护性（defensibility）”的系统化综述。核心问题不是系统能不能产出论文，而是：产出的 claim 有什么证据、谁能检查、检查失败后谁有权阻止发布。

中心综合

生产能力快于阻断能力

系统已经能写、跑、分支和提交，但仍缺少覆盖整篇论文、可阻止发布的 G-paper-full 架构。

作者如何构建这张文献地图

1. 搜索不是固定关键词一次抓取，而是迭代闭包

主要搜索首次公开于 2025 年 1 月至 2026 年 6 月的工作，同时保留 2023–2024 年的重要前驱。来源包括 arXiv、Semantic Scholar、DBLP、OpenReview、Google Scholar、会议页面、GitHub artifact 页面、Benchmark 页面和项目文档。作者从已读论文继续抽取机制名、失败模式、作者线索、引用与相关工作，反复扩展，直到新一轮不再改变活跃来源集或综合结论。

2. 纳入五类对象

系统

自动化多个研究活动的 workflow，例如构思、检索、实验、分析、写作与评审。

Benchmark

测研究 agent、重构、soundness、tool use、memory、deployment 或人机交互。

Verifier / Audit

执行检查、形式或统计门、证据包、对抗审查、provenance 与 gating。

领域系统

生物、化学材料、物理天文、医学、工程计算机与量子研究。

Agent-native artifacts

技能、来源记录、sidecar、可复用研究包及自改进控制器。

3. 每篇文献先进入结构化 evidence record

固定字段包括：书目信息、研究对象、系统或 Benchmark pipeline、技术机制、评测设置、报告结果、明示/推断局限、artifact 可用性、verifier/judge 类型、人类角色、失败模式及对本文综合的意义。Benchmark 额外记录任务规模、数据源、scorer、最强外部检查及不可见证据；verifier 额外记录目标对象、证据访问、与生成器的独立性，以及负面判断能否 block/revise/rerank。

4. 系统按“最强公开证明”保守编码

G、O、P、A、DC-Evidence 与 R-grade 不是按营销口号编码，而是按公开机制、artifact、评测或 trace 所能证明的最强能力编码。无法检查的广泛声称会降到较低标签，并记录 claim–evidence gap。

R-grade 如何得到？

五个维度各打 1–5 分：C1 Evidence Grounding、C2 Verification Independence、C3 Failure and Limitation Disclosure、C4 Reproducibility、C5 Substantiation。总分 22–25 为 R5，17–21 为 R4，12–16 为 R3，7–11 为 R2，5–6 为 R1。

注意：R-grade 衡量的是公开证据强度，不是系统能力。一个很窄但证据扎实的基础设施可以高于一个功能很广但难以核验的端到端系统。

方法学边界：这不是完整 PRISMA census；原始去重前检索命中没有归档；全语料没有做双人编码，因此不报告 inter-coder agreement。作者用明确规则、保守编码和边界注释缓解主观性，但没有消除它。

Benchmark 与 Verifier：作者整理结果，但没有统一复跑

§4 把 Benchmark 当作“让失败可见”的工具，把 verifier 当作“让失败产生阻断后果”的机制。同一个 instrument 有时兼有两种角色，但大多数只能覆盖局部对象。

Benchmark target

Reconstruction

MLReplicate、PaperBench、SciReplicate-Bench、PaperRepro、CORE-Bench：能否从论文记录恢复代码、运行或论文级 artifact。

Benchmark target

Optimization

MLE-Bench、RE-Bench、HeuriGym、FML-Bench v2 等：能否在外部 scorer 下搜索出更高分的程序或方案。

Benchmark target

Process Quality

ResearchArena、AutoResearchBench、DeepScholar-Bench、EngTrace、DR3-Eval：过程是否像严谨研究，而非只看最终分数。

Benchmark target

Soundness

MLR-Bench、SoundnessBench、SPOT、FLAWS、SciIntegrity-Bench：可信外观下是否仍有伪造、错误或不受支持的 claim。

读数原则：论文引用的 “MLE-Bench 17% Any Medal”“SPOT 最佳 recall 21%”“MLReplicate 自动—人工相关 r=0.29”等数字，是对各来源报告结果的综合，不是本 survey 在统一模型与预算下得到的新结果。论文自己也提醒，R&D-Agent 的 35% 与 MLE-Bench 的 17% 使用不同模型和计算预算，不能当作 like-for-like 改进。

LLM judge 的结构性上限：论文把 SPOT 的 21% 错误召回、SoundnessBench 的 26% 低-soundness 识别、BadScientist 最高 82% 操纵样本通过，以及 MLReplicate 59% 自动接受稿含不支持 claim 放在一起，说明“多加几个 judge 或 rubric”并不会自动引入独立外部证据。

论文认为真正缺失的是 Full-Paper Release Gate

G-paper-full 不是更长的评分 rubric，而是一个对整篇论文拥有 release authority 的验证架构。它必须让生成器无法靠改写措辞绕过负面证据。

1. Claim extractor抽取数字以外的因果、创新、范围、解释与局限主张
2. Counterevidence调用生成器不能控制的文献、数据、工具与领域证据
3. Claim graph把支持与矛盾定位到句子、表格、图、run 和引用
4. Reconciliation可修复则修订；未解决则阻断，而不是仅写一条评论
5. Human authority机器证据不足时升级给领域科学家，并记录批准或否决

论文给出的四个近期里程碑

M1

Claim-extraction Benchmark

由作者确认 causal、novelty、scope、limitation、interpretation claim，按类型报告 extraction F1。

M2

Counterevidence Index

保留 hold-out 文献与数据，对 seeded prior-art conflict 报告召回率。

M3

Claim-graph Schema

记录 span-level claim–evidence–contradiction 三元组，并能解析到具体 run、表格和引用。

M4

Reconciliation Harness

消费 M1–M3，保留 human veto，报告 gate 结果、矛盾吸收与决策责任人。

最重要的概念跃迁：当前工具分别解决“发现失败”或“阻止局部对象”；论文主张下一步应把 Benchmark 与 verifier 成对设计，让 Benchmark 定义必须检查的 claim 类型，让 verifier 找反证，并让 gate 真正改变 release 决策。

三条中心结论，以及可信度边界

Finding 1

Production outran verification

系统已能生成 submission-like artifacts，但 fabrication、unsupported claims 和过度乐观的 proposal 评分仍普遍存在。

Finding 2

Typed target 上的局部 gate 有效

程序、run、contract、hidden grader、部署、样本、设备或重现数值都能被可靠 gate；这些 gate 不自动覆盖论文解释。

Finding 3

A2 让证据更靠近文字

结构化 artifact 提升可检查性，但没有自动赋予 reviewer 或 verifier 阻止发布的权限。

这篇论文的强项

  • 把“产出范围”“公开证据强度”“verifier 能看到什么”“gate 能阻止什么”拆开，减少了 end-to-end 标签带来的概念混淆。
  • 对边界采取保守规则，例如 tree search 不自动算 reviewer loop，人工 checkpoint 不自动算 autonomous gate。
  • 负面发现可被公开反例证伪：一个公开 O2 dispatcher trace、P2 controller 或 G-paper-full gate 就能改变结论。
  • 跨六类 science 对照，说明 local-evidence / paper-claim 边界不只是 ML 特例。

如果你想做真正的“统一实证比较”，还缺哪一步

这篇论文非常适合用来定义比较维度和寻找研究空白，但它本身不是你此前设想的“选择多个系统、统一实现、统一跑 Benchmark”的实证研究。后者可以把这篇综述当作 sampling frame 和 taxonomy，再增加受控实验层。
