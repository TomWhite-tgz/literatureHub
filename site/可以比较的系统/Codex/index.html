§在科研 agent 谱系里的位置

Codex 不属于"科研 agent"那一类。它是一个面向工程实操的 coding agent——和 Claude Code / Cursor 同一层。但它的源码结构对搭科研 agent 极有参考价值：它把"agent 循环 / 工具执行 / 沙箱隔离 / 多前端接入"切成正交的 crate，每一层都能单独复用。

项目核心抽象执行隔离前端接入
AgentScope深 ReAct Agent + 中间件6 种沙箱后端FastAPI 服务层
Codex 👈Session + Turn + CodexThread（异步任务）Linux bwrap+seccomp / macOS Seatbelt / Windows restricted tokenapp-server（JSON-RPC）→ TUI / IDE / exec
InternAgent状态机 + 11 个专职 agent外包给 shell/openhandsCLI + benchmark
★ 关键洞察：Codex 把"一个 agent 会话"做成 CodexThread，它是事件流而非同步函数 AgentScope 的 Agent.reply() 是一个会跑完的 async 调用；Codex 的 CodexThread 是一条双向消息流——客户端发 Op::UserInput，thread 回吐 Event 流（token、工具调用、diff、完成）。
这个设计的代价是状态管理复杂（Session / SessionState / TurnContext 三层），收益是天然支持多消费者：TUI 与 exec 走 in-process app-server，IDE/daemon 可走进程外 transport；MCP server 则是另一条把 Codex 能力向外暴露的适配路径，不能简单算作 app-server client。

阅读路线：主干四篇 + 两篇补全

① Agent loop

逐函数精读 run_turn 的 loop { ... }：采样 → 流式事件 → 工具调用 → 回到采样。附关键源码。

② 执行 & 沙箱

apply-patch 的 patch 模型；linux-sandbox 当前默认的 bubblewrap+seccomp 与 legacy Landlock 路径；execpolicy 的命令准入。

③ app-server & TUI

app-server 如何把 CodexThread 暴露成 JSON-RPC；TUI 的 ratatui 事件循环与渲染管线。

④ 结论

一句话：Codex 是"事件流内核 + 沙箱执行 + 多前端 RPC"的三层正交设计。
补全阅读 先读 ①②③ 理解运行主干，再读 ⑤ 看工作区全景；⑥ 是 2026-08-08 的事实审计，明确列出 Codex 的七个突出优点，并把源码机制映射到 AutoResearch 的 run/event/artifact/evidence 设计。若只想看结论，直接读 ⑥ 优点与 AutoResearch 借鉴。

crate 切分一览

Codex 把代码按"能独立编译的边界"切 crate，而非按目录。审计快照中共找到 137 个 Cargo.toml（这只是包清单文件数，不等同于 137 个 workspace member）；下表只列与本篇相关的核心 crate。

crate规模职责本篇章节
core417 文件 / 18.8 万行agent 循环、Session、Turn、compact、MCP 客户端、tool router①
exec12 文件 / 5.5 千行非交互入口 codex-exec，JSONL/human 输出②③
apply-patch7 文件 / 4.6 千行解析并应用 *** Begin Patch 格式补丁②
linux-sandbox13 文件 / 7.0 千行bubblewrap + seccomp 默认路径、legacy Landlock 回退，codex-linux-sandbox 二进制②
execpolicy12 文件 / 2.0 千行命令行准入策略（allow/deny/ask）②
app-server93 文件 / 4.6 万行JSON-RPC server，托管 CodexThread，stdio/websocket/in-process 三种传输③
app-server-protocol51 文件 / 3.1 万行RPC 协议类型（ClientRequest / ServerNotification / Thread / Turn）③
mcp-server12 文件 / 3.0 千行把 codex 会话作为 MCP 工具暴露给外部 MCP 客户端③
tui411 文件 / 24.2 万行ratatui 终端 UI，通过 app-server-client 接入③
为什么 tui 有 24 万行？ TUI 是整个 repo 最大的 crate。它不只是"画界面"——它包含完整的 chat widget、流式 markdown 渲染、diff 渲染、onboarding、resume/fork picker、通知系统、宠物彩蛋，以及一套和 app-server 对等的 client 逻辑。本篇 ③ 只讲它的骨架（entry → event loop → render），不展开 411 个文件。
