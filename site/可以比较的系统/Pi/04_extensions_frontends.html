④ 扩展与前端：一个内核，多种进程边界

Pi 的 extensibility 很强，但安全模型也因此非常直接：扩展就是与 agent 同权限的代码。

扩展能改到哪里

扩展面能力
Tools注册新工具、动态切换 active tools、自定义 call/result renderer
Lifecycle hooksinput、before agent、context、provider headers/payload/response、tool、compaction、branch、session
UIconfirm/select/input/notify、status/widget、overlay/custom component、快捷键
Commands/resourcesslash command、flag、prompt template、skill、theme、provider
Persistenceappend custom state 或 custom message，恢复时按 customType 重建

ExtensionRunner 按加载顺序执行 handlers，并隔离多数 handler 异常；tool interception 可以 block/transform，message-end hook 可替换最终消息。异步 factory 会在 session_start 前完成，适合动态 provider discovery；长期 socket/process 则应延迟到 session 生命周期并在 shutdown 清理。

证据：packages/coding-agent/docs/extensions.md；packages/coding-agent/src/core/extensions/runner.ts；packages/coding-agent/src/core/extensions/types.ts。

project trust 的真实作用

只加载 global/CLI extension→project_trust 决策→设置 trusted state→重载 settings/packages/extensions/skills/prompts

ResourceLoader 先强制 untrusted 做 bootstrap，项目内设置、包和扩展此时不加载；用户或预信任 extension 决定后，再按信任状态 reload 完整资源。这能防止“为了询问信任，先执行了项目代码”的启动漏洞。

证据：packages/coding-agent/src/core/resource-loader.ts:380-465,553-623；packages/coding-agent/src/core/project-trust.ts。
但 trust 不是 sandbox。一旦加载，extension 可以执行任意代码并拥有完整系统权限。项目 trust 解决“是否加载”，不解决“加载后能访问什么”。Pi 文档明确要求只安装可信扩展。

四种主要消费方式

边界适用场景语义
Interactive TUI人机协作 CLI直接订阅 AgentSession；最完整 UI 与扩展交互
SDK同进程 TypeScript 应用直接创建 AgentSession，避免子进程协议成本
JSON event mode单次 headless 集成stdout JSONL；stream update 仅发送 delta，message_end 是权威终态
RPC modeIDE/外部 UI 控制长期子进程stdin/stdout JSONL request/response + async events；prompt acceptance 与后续执行结果分离

JSON/RPC 的线性 stream 是经典 AgentSession 的 adapter，并不是下一代 CBOR server。RPC 明确规定只按 LF 分帧，避免通用 line reader 把 Unicode line separator 错当记录边界；busy 时 prompt 必须声明 steer/follow-up，否则拒绝。

证据：packages/coding-agent/docs/json.md；packages/coding-agent/docs/rpc.md；packages/coding-agent/src/modes/。

TUI 不是一坨 CLI 输出

pi-tui 抽象共同 TUI interface，提供 main-screen 与 alternate-screen renderer。组件只返回 ANSI lines；renderer 做宽度验证、overlay composition、cursor 定位与 differential update。主屏实现查找 firstChanged / lastChanged，只重画变化范围，并用 CSI 2026 synchronized output 原子提交，保留终端 scrollback。

Main screen

终端拥有 scrollback；适合传统 CLI 文档流。宽/高变化或不可安全定位时全量重画。

Alt screen

应用拥有固定 viewport、scroll view 和 layout；退出时恢复主屏并打印最终完整文档。

证据：packages/tui/README.md；packages/tui/src/tui-main-screen.ts:197-531；packages/tui/src/tui-alt-screen.ts。

架构判断

Pi 不是“所有前端都经过统一 server”的系统。当前 Interactive/SDK/JSON/RPC 共享 AgentSession 语义，却有 in-process、stdout 和 stdin/stdout 多种边界；实验性 server/client 是另一条尚未接管主 CLI 的路线。它比强制中心 server 更轻，也意味着不同 adapter 的 capability 与版本治理需要分别维护。
