② 模型与工具：provider 拥有行为，loop 只认契约

Pi 没有把多模型支持写成一串 agent 内的条件分支，而是让 provider 自己拥有认证、模型目录与 stream 行为。

三层模型抽象

层职责关键点
Modelprovider/id/api、上下文窗、cost、thinking 能力、compat flags纯描述对象，可被持久化引用
Provider认证、静态/动态模型列表、stream、deferred fetch/cancel具体 API 行为归 provider，不归全局 registry
Modelsprovider 集合、认证解析、refresh、header merge 与 dispatch调用前解析 credential，把请求委派给 model 所属 provider

Models.refresh() 并发刷新已配置的动态 provider，错误按 provider 收集而不是让整个 refresh reject；stream 路径则把认证失败转为流错误。这个区分适合 UI：目录刷新可以部分成功，真实推理请求必须明确失败。

证据：packages/ai/src/models.ts:39-232,254-735；packages/ai/src/types.ts:17-320,794-823。

消息协议是共同最小面

所有 provider 最终收敛到 UserMessage / AssistantMessage / ToolResultMessage，assistant content 由 text、thinking、toolCall 组成；流式事件用 content index 和 delta 增量更新，终态才给出 stop reason、usage、错误或 deferred handle。coding-agent 自己的 bash/custom/branch/compaction message 先经过 convertToLlm 投影，避免 UI 状态直接污染 provider 协议。

可迁移点：业务 transcript 可以比 provider message 更丰富，但必须有一层显式 projection。AutoResearch 的 evidence、checkpoint、review decision 不应假扮 user message；应在构造模型 context 时选择性投影。

工具 batch：并行执行，稳定写回

默认 batch 并行；只要任一被调用工具声明 executionMode: "sequential"，整个 batch 就顺序执行。并行模式先依次完成 schema validation 和 beforeToolCall，随后并发执行允许的工具：

  • tool_execution_end 按物理完成顺序发出，UI 能及时显示快任务。
  • Promise.all 保持输入数组顺序，最终 toolResult messages 按模型 tool-call 顺序进入 context。
  • afterToolCall 可以改写 content/details/error/usage/terminate。
  • validation、block、throw、abort 都被规范成 tool result，不留下孤儿 tool use。
证据：packages/agent/src/agent-loop.ts:411-650；工具类型见 packages/agent/src/types.ts。

coding-agent 的默认工具不是全部工具

SDK 默认启用 read / bash / edit / write，还提供 grep/find/ls 和自定义工具工厂。allowedToolNames、denylist 与 active tools 决定本轮暴露集合；扩展可注册工具，并通过 tool-call/tool-result hooks 拦截或改写。系统 prompt 根据当前 active tool 的 snippet 与 guideline 动态生成，而不是硬编码“永远存在 Bash”。

证据：packages/coding-agent/src/core/sdk.ts:169-393；packages/coding-agent/src/core/tools/；packages/coding-agent/src/core/system-prompt.ts。

权限：有 hook 点，没有内建安全边界

beforeToolCall 可以实现 permission gate，项目扩展也能弹确认框；但这不是默认权限系统。README 明确把 permission popup 留给扩展，并建议需要隔离时使用容器。工具、扩展与进程共享启动用户的文件系统、进程、网络和凭据权限。

不要混淆三件事：tool allowlist 控制“给模型看什么”；project trust 控制“加载哪些项目资源”；sandbox 控制“进程实际上能碰什么”。Pi 默认具备前两者的一部分，但第三者依赖外部容器/隔离环境。
