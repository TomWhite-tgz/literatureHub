先说结论

Pi 最值得研究的不是功能最多，而是把层次切得很薄：pi-ai 统一 provider 与消息流，pi-agent-core 只做 turn/tool/queue 循环，pi-coding-agent 再接会话、压缩、资源与 UI。它有意不内建 MCP、subagent、permission popup、plan mode 和后台 Bash；这些能力留给扩展、外部进程或容器。

一句话架构：当前可用产品主线是 CLI/SDK → AgentSession → Agent → agentLoop → Models/provider；另一条 server → AgentHarness → durable session 是面向崩溃恢复和多 lane 的下一代设计，但执行层大多仍为脚手架。

值得带走的核心判断

  • 小内核不是少功能，而是把策略推迟。经典 loop 只规定消息、工具结果和队列的正确闭合；coding-agent 与扩展决定产品行为。
  • 并发完成顺序与上下文顺序被刻意分离。工具可并行，live end event 按完成顺序；写回模型上下文的 tool result 仍按模型调用顺序。
  • 会话树比线性 chat log 更接近真实工作。branch、compaction、model/thinking change、custom state 都是 append-only entry。
  • 安全默认是“继承进程权限”。project trust 只控制项目资源是否加载，不是工具执行沙箱；强隔离要靠容器或自定义扩展。
  • 下一代 Harness 的设计质量高于当前完成度。它提出了 durable acceptance、effect boundary、recovery matrix 和 lane isolation，但产品比较必须以实现为准。
