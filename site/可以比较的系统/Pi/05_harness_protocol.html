⑤ Harness v2：优秀的恢复设计，尚未成为运行时

这一页刻意分成“设计目标”“已实现底座”“未实现执行”，避免路线图污染源码结论。

设计文档想解决什么

harness-v2.md 把一次被接受的 prompt 当作 durable operation，而不是内存中的 Promise。一个 session 可以有多条 named lane，每条 lane 最多一个 operation，不同 lane 可并行；所有外部 effect 前先写 intent，完成后再追加 result entry。恢复时根据 durable prefix 决定继续、合成中断结果或安全重放。

设计不变量意义
Durable acceptanceprompt 一旦 accepted，进程崩溃后仍能发现 open operation
Per-lane mutation line同 lane 写入串行，不同 lane 并行；服务层保证 single writer
Effect boundary / manual drive每个 write/provider/tool/hook/sleep 都可在测试中逐步释放，枚举 crash prefix
Intent before effect工具执行前持久化 tool_started 与 provisioned result id
Replay declaration只有历史 record 与当前工具都声明 replay-safe 才允许崩溃后重跑
Append-only provider context一轮内中途到达的写入延迟到 checkpoint，保护 cache prefix

session 设计比 v3 更强

format-4 将状态拆成四类：append-only tree entries、lane leaf pointers、operation records、latest-wins facts，并共享单调 seq。orchestration records 不进入模型 context。队列又细分为 steer/follow-up、可跨 abort 的 nextRun 和 pending writes；usage 单独记账，失败 provider attempt 也不丢成本。

设计还覆盖 deferred provider handle、overflow recovery 上限、watch snapshot 无缝接事件、abort 后合成 tool result、bounded restore query，以及 old coding-agent v3 的只读 normalization/首写转换。

设计证据：packages/agent/docs/harness-v2.md，尤其 sections 2-15、19-21。

最容易误读的一处

packages/coding-agent/src/server/create-harness.ts 已能把 read/bash/edit/write、system prompt 和 execution env 组装成 AgentHarness.create() 参数。这证明 coding-agent 正在准备 server 接线，但不证明 server 已能运行 prompt：创建出的 harness 仍使用上面的 placeholder operation methods。

审计规则：“有 adapter”“有 public type”“有 3,400 行规范”都不等于 feature complete。判定运行能力应沿入口调用到 concrete method；这里最终落到 unavailable()。

实验性远程协议

protocol v1 使用 [uint32-be length][definite-length CBOR]。首包必须是带版本的 hello，后续是关联 request/response 和 server event。snapshot 是权威状态，progress event 只供 UI 展示，不能乐观 fold 成真相。transport 负责在协议字节交换前完成认证；Unix socket 依赖文件权限，网络 transport 必须另做认证。

client 支持一个连接 attach 多 session，并用 shared/exclusive lease 管本地 ownership；不会自动重连。server 本身不提供 standalone CLI 或 coding-agent service，应用必须注入 session/model/storage service。

证据：packages/protocol/README.md；packages/server/README.md；packages/client/README.md。

给 AutoResearch 的用法

Harness 文档最值得借的是验证方法：把每个外部 effect 前后的 durable prefix 都变成可重开测试，并把 replay safety 写入 tool declaration。无需等待 Pi 完成，也不应复制它尚未验证的全部 API。AutoResearch 可以先实现单 lane、单 writer、action intent/result 与 manual effect gate，再扩展并行 lane。
