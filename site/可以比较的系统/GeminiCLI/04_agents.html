④ 子 Agent：一个工具入口，两种执行后端

invoke_agent 对主模型只有统一 schema；registry 决定可选角色，local executor 跑独立 ReAct loop，remote invocation 把请求桥接到 A2A。

统一入口：模型只看到 agent_name + prompt

main model → invoke_agent({ agent_name, prompt })
  → AgentRegistry.getDefinition(agent_name)
  → 把 prompt 映射到该 definition 的单一 input key
  → DelegateInvocation
      ├─ local  → LocalSubagentInvocation → LocalAgentExecutor
      └─ remote → RemoteAgentInvocation   → A2AClientManager

如果 definition 的 input schema 恰有一个 property，prompt 会映射到那个键（如 request/objective/question）；否则保留为 {prompt}。DelegateInvocation 在确认和执行时都会重新构造具体 child invocation，所以 policy 确认与真正执行使用相同 agent definition。

多个 invoke_agent 在主 Scheduler 中没有被强制顺序化，因而同一 model batch 可并行；但 local executor 在复制工具时明确过滤 Kind.Agent，所以子 Agent 不能再调用子 Agent。它是“一层 fan-out”，不是递归 agent tree。

Definition：角色、资源与退出协议都声明化

字段含义
inputConfigAJV/JSON schema，规定委派输入
promptConfigsystem prompt、few-shot initial messages、首个 query template
modelConfig模型、thinking、temperature 等；可 inherit
toolConfig工具名、MCP wildcard、实例或 function declaration
outputConfigZod schema、输出字段及可选 postprocessor
runConfigmax turns / max time，默认 30 turns / 10 minutes
scope 字段附加 workspace、memory inbox、extension context、inline MCP 等窄授权

local 与 remote 共用 name/description/input/output metadata；local 才拥有 prompt/model/run/tools，remote 则用 Agent Card URL/inline JSON 与 auth config。Definition 因而不是“另一段 prompt”，而是一个可验证的执行契约。

Registry：内建 → 项目 → 用户 → 扩展，但先注册者占名

初始化先注册内建 codebase_investigator、cli_help、generalist，按设置可加入 browser agent；再扫描项目 .gemini/agents/、用户目录与 extension agents。这里有一个容易按注释读错的细节：registerAgent() 注释称后者覆盖，但实现检测到同名不同对象后 warning 并 ignore later definition。所以实际 name precedence 是更早来源优先，内建名字也被保留。

项目 agent 还受 folder trust 约束。每个 Markdown 内容算 SHA-256；未确认的 hash 只发 discovered event，不进入 active registry。文件内容变更会改变 hash，要求重新 acknowledgment。用户目录与 extension definition 没走这套项目 hash 确认。

experimental definition 默认 disabled，可用 settings override 开启；local override 可改 model/run/tools/MCP。model 改变时 local definitions 会 refresh；reload 会清 A2A client/card cache并报告新增、更新、删除。

Local executor：独立 registries，共享 policy 与系统服务

每次 invocation 新建 Tool/Prompt/Resource registries，并从父 registry 按 definition 克隆工具到派生 MessageBus；agent 自带 MCP server 也被发现到这些局部 registries。这样工具实例状态和 MCP 可见性隔离，但 Config、PolicyEngine、Gemini client、sandbox manager 仍来自父 context。所有 local agent 额外注册强制 complete_task。

workspace extension 通过 AsyncLocal scope 暂时扩展，不修改共享 Config；filesystem root 会被拒绝。memory inbox 和 auto-memory extraction 也各用窄 scope。这比给整个子 Agent 复制一份全局配置更适合并行执行。

packages/core/src/agents/local-executor.ts:120-317, 540-570

Local loop：只有 complete_task 才算完成

template inputs/runtime→独立 GeminiChat→model function calls→Agent Scheduler→function responses↻

每轮先做 legacy chat compression，再运行 definition 的 onBeforeTurn，随后调用模型。没有任何 function call 却未调用 complete_task 被视为协议错误；只有 completion tool 返回 taskCompleted 才得到 GOAL。普通 tool denial 是“软拒绝”：响应会指导模型换策略，loop 不立即 abort；真正外部取消才终止。

达到 timeout、max turns 或无 completion call 时，还有一个短 grace turn：只允许模型立即调用 complete_task 交付 best-effort。等待用户确认期间 deadline timer 暂停，不把人的思考时间算进 agent budget。默认终止类型还区分 ERROR、TIMEOUT、GOAL、MAX_TURNS、ABORTED 与协议错误。

packages/core/src/agents/local-executor.ts:329-489, 540-905, 1055-1095, 1097-1329, 1455-1471

工具执行仍走主 Scheduler，不是子 Agent 后门

模型返回 calls 后，executor 先校验参数和局部 allow set；越权工具被转成同 call id 的 error response。合法 calls 交给一个短生命周期 Scheduler，携带 subagent name、parent call id 和专属 registries，因而继续执行 before-tool hooks、PolicyEngine、confirmation、sandbox 和批次并行。结束后结果写入该 subagent 的独立 chat recording。

确认请求使用从父 MessageBus derive 的 bus，携带 subagent identity；main TUI 能看到是谁请求了什么。活动另翻译成 thought/tool start/tool end/error，并做内容与参数 sanitization 后作为 SubagentProgress 实时输出。

用户 steering：local 是直播订阅，remote 是调用前快照

local executor 启动后订阅 InjectionService，把新的 user steering 与 background completion 排入队列，在下一轮 function-response message 前置注入；因此正在运行的多个 local agents 都能收到后续 hint。remote DelegateInvocation 记录创建时 injection index，在确认/执行构造 child invocation 时，把此后 user steering 拼到原 query；A2A 流开始后则没有同样的逐轮本地注入点。

packages/core/src/agents/local-executor.ts:624-757；packages/core/src/agents/agent-tool.ts:145-236

Remote A2A：card 决定协议，客户端重组流

registry 加载 remote definition 时解析 Agent Card，把用户描述、card description 与 skills 合并；auth 支持 API key、HTTP、Google credentials、OAuth2。取 card 先匿名，401/403 才带 auth 重试；调用传输同时注册 REST、JSON-RPC、gRPC，由 SDK/Card 协商。远程长任务使用 30 分钟专属 transport timeout。

A2AResultReassembler 把 Message、Task、status update、artifact update 的增量重新拼为文本和 activity。每个 chunk 还提取 contextId/taskId，后续同 agent invocation 继续对话；task 完结时可清 taskId。远程调用即便中途失败也保存已获得的 ID。

这种连续性是进程内的，不是 session JSONL 的 durable 状态。legacy implementation 的 static Map 只按 agent name；新 session adapter 改为 name + target URL，但相应 agentSessionSubagentEnabled 默认仍为 false。CLI 重启后两者都会丢失。

AgentSession 迁移：统一事件面，不替换执行内核

开关开启时，DelegateInvocation 选择 Local/Remote SessionInvocation。LocalSubagentProtocol 内部仍创建并运行 LocalAgentExecutor，只是把 activity 翻译为统一 agent_start/message/tool_request/tool_response/error/agent_end 事件；remote protocol 同理包裹 A2A stream。父 session 可以 subscribe，外部 abort 也统一代理给 protocol。

所以这次迁移的价值主要是“统一生命周期与可观察性协议”；它不是新 planner，也没有改变 local loop 的 completion、policy 或工具边界。

本章结论

  • invoke_agent 是普通受治理工具；并行委派可行，但 local 子 Agent 被明确禁止递归委派。
  • definition 同时界定 prompt、model、tools、workspace、budget 和结构化完成协议，远比角色提示词更完整。
  • local agent 有隔离 history/registries，却共享 policy、sandbox 与确认通道；它不是权限逃逸边界。
  • remote A2A 有协议协商、鉴权和流重组，但 context/task 连续状态目前只存在内存。
  • AgentSession 路径统一事件 API，当前默认关闭，底下仍复用成熟 local/A2A 后端。
