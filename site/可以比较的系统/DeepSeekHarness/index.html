先说结论

DeepSeek Harness（下文简称 DSH）不是 Pi loop 的换皮，也不是“DeepSeek API + shell”。它的核心是一个可热替换的插件化 Agent 操作系统：Cordis 负责服务依赖、作用域、事件与可逆生命周期；dsh-agent-loop 只拥有 turn/step 状态机；模型、工具策略、持久化、压缩、权限、subagent、目标和 UI 都在循环外通过服务与事件接入。

一句话调用链：dsh argv → profile patch stack → Cordis Loader → AgentLoop.create/resume → ReactLoopAgent.turn → preStep → buildRequest → LlmService/adapter → tool scheduler → Session.append → deriveMessages → 下一 step。

它与 Pi 的关系，先避免一个误区

DSH 既借用了 Pi，也超出了 Pi。@deepseek-ai/dsh-llm-pi-ai 直接依赖 @earendil-works/pi-ai ^0.82.1，把 Pi 的多 provider/model/stream 层适配成 DSH 的 LlmAdapter；但 DSH 没有复用 Pi 的经典 pi-agent-core loop、AgentSession 或 JSONL 树。也就是说，Pi 在 DSH 内是可选模型后端，不是运行时母体。

贯穿全文的三个判断

  • 权威状态不是 Agent 对象，而是 Session 日志。Agent 是活跃驱动器；恢复、模型历史、UI、token 统计、遥测和 fork 都从事件投影。
  • 扩展点不是 callback 大杂烩，而是 Service + typed event + scope。插件既能提供能力，也能用 waterfall 拦截决策，还能在 agent 私有 context 中覆盖全局注册。
  • 复杂度换来了明确的失败与恢复边界。创建前准备、发布、反向 teardown、请求 header、工具 call/result、压缩替换和审批问答都被结构化记录；代价是包图、事件顺序和生命周期学习成本很高。
