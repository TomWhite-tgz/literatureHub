④ 会话与上下文：日志不变，表面可替换

DSH 同时保留完整事件历史和一个可压缩的模型可见 surface；这比“messages 数组”多一层，却把审计与上下文缩减统一起来。

Session 是普通对象，SessionStore 才是服务

Session 是 append-only event log；SessionStore 作为 ctx.sessions 管活实例、作用域通知和 flush。持久化故意不写进 Session：backend 订阅同步 session/event，异步批量写，在 session/flush checkpoint 等待落盘。

Session header 保存 id、version、cwd、parent lineage、seed length、delegation depth 等创建元数据，不混入 replayable 对话事件。恢复 seed 必须从 seq 0 连续，逐条通过与 live append 相同的 JSON 与 surface invariant；构造完会写 session/end-seed 标记内存/持久历史边界。

证据：packages/core/session/src/index.ts:430-563,801-903。

append() 的类型把错误提前到编译期

append<T extends SessionEventType>(
  type: T,
  data: SessionEventMap[T],
  ...opts: T extends SurfaceEventType ? [opts: SurfaceIntent] : []
): SessionEvent<T>

若 type 是 user/message、assistant/message 或 tool/result 这类能进入模型历史的事件，条件 tuple 强制第三个参数存在；若是 turn/start 或 chunk，第三参反而禁止。SessionEventMap[T] 又保证 event type 与 payload 对应。这是很典型的 TypeScript：不是只给编辑器提示，而是把领域不变量编码进函数签名。

运行时仍要验证，因为持久化 seed、JSON、插件和 wire 是不可信边界。append 拒绝 BigInt、NaN、循环引用、稀疏数组、Map/Set/Date/class instance 等不能无损 JSON 化的值；接纳后深冻结，旧的 events snapshot 不随新 append 长大。

证据：packages/core/session/src/index.ts:565-670。

原始日志与模型 surface 是两条不同视图

每个 message-producing event 必须带 surfaceOp：

  • 'append'：加入 surface 尾部；
  • {op:'replace', start, end}：用当前事件替换 surface 上一个连续范围。

replace 不删除旧事件，只让新节点遮蔽它们，并通过 sourceEventSeqs 记录来源。SurfaceManager 验证范围存在、顺序正确、所有被遮蔽节点都在 provenance 中；tool-result 的单节点替换还限制只能改 content。于是完整 transcript/chunks/压缩过程可审计，而发给模型的 history 可以变短。

event log:  user₀ assistant₁ tool₂ result₃ ... compact/summaryₙ
surface:    [user₀ assistant₁ tool₂ result₃ ...]
replace:    [summaryₙ ...retained tail...]   // 旧事件仍在 log
证据：packages/core/session/src/types.ts:208-393；packages/core/session/src/surface.ts:22-397。

deriveMessages() 是增量投影

模型历史不从 raw log 简单 filter，而是遍历 surface 的 seq 列表，对每个节点运行同一个 deriveEventMessage()。普通 append 后只投影新节点；replaceGeneration 改变时才清空缓存重建。返回的是新数组，但 Message 对象共享深冻结的事件数据，既避免重复 clone，也不让调用方篡改历史。

这实现仓库强调的规则“model-visible ⇔ logged”：system prompt 和 tools 不是 message event，因此单独折进持久 request/header；route/capacity 是 request/context。给定日志前缀，可以重建当时每次请求的 messages + header，而不依赖进程内对象。

证据：packages/core/session/src/index.ts:672-773；packages/core/agent-loop/src/agent.ts:435-470。

持久化：热路径同步提交，I/O 在 checkpoint 对齐

append 一旦进入内存日志就算提交；observer 错误被隔离，不能回滚事实。persistence plugin 将 session/event 复制进有界写批次。SessionStore.flush() 收集 scoped listeners，以 Promise.allSettled 等全部完成后报告第一个失败。默认 checkpoint policy 在每次模型请求与顶层工具 dispatch 前 flush，在 turn/end 后、下一 turn/idle 前再 flush。

默认 backend 是 JSONL，但仓库同时提供 SQLite backend；二者实现同一 persistence seam。JSONL 使用带校验和的 Zstandard packed session，不能把文件扩展名理解为“一行可随便 append 的裸文本”。

证据：packages/core/session/src/index.ts:584-670,1023-1060；packages/session-persistence/；packages/bundle/base/cordis.patch.yml:97-100,328-330。

fork 与 resume 不是同一种操作

resume 从 persistence 恢复同一 id 的完整历史与 header；fork 复制一个已闭合 turn 边界以前的前缀，生成带 parentSession/seedLength 的新 session。fork 拒绝不存在或非 live source、重复 child id、非法边界以及落在 open turn 内的切点。subagent-fork 在创建时只捕获一次父前缀；后续激活沿用 child 自己的 session，不会重新吸入父亲的新历史。

compaction 是一次持久 surface transaction

compact-basic 在 agent/pre-step 检查正常压力，在 agent/request-error 识别 provider-confirmed context overflow。一次摘要以 compact/start → compact/summary(replace) → compact/end 闭合；模型无关的 oversized tool-result prune 先发生。overflow retry 只有 surface 取得持久进展才有意义，并受计数限制，避免“同样的上下文无限重试”。手动压缩通过 maintenance 与 turn 串行化。

与截断最不同的是：摘要节点知道自己遮蔽了哪些 seq、当时 token shadow price 是什么，完整旧历史仍可供 replay/审计。缺点是 surface balance、turn closure、孤儿 compaction 修复都必须维护严格 invariant。

证据：packages/compact/compact/src/{index,types,invariant}.ts；packages/compact/compact-basic/src/index.ts:122-221。
架构判断：Pi 的 JSONL entry tree 擅长人类分支与 session navigation；DSH 的 event log + replaceable surface 更像 event-sourced runtime，擅长让压缩、工具结果改写、请求重建、UI 和遥测共享同一事实流。DSH 的语义更严格，也更难手工编辑和理解。
