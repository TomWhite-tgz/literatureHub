⑥ 用 DSH 学 TypeScript：类型在表达协议

这一章不从“number/string 是什么”开始，而是解释阅读 DSH 最常遇到、也最能体现 TypeScript 价值的语法。

先认清编译环境

仓库是 ESM：package.json 有 "type":"module"，源码相对 import 明写 .ts；编译器用 target: es2024、module: esnext、strict: true。三个严格选项尤其影响阅读：

  • noUncheckedIndexedAccess：array[i] 推导为 T | undefined，所以在已证明边界后常见 group[index]!。
  • exactOptionalPropertyTypes：x?: string 表示“属性可缺失”，不自动等于“属性存在且值为 undefined”。因此源码大量用条件 spread 省略字段。
  • noImplicitOverride：子类覆盖父类方法必须写 override，例如 adapter 的 override providerInfo()。
证据：package.json；tsconfig.base.json。

interface、type 与 class

语法适合表达DSH 示例
interface可扩展的对象契约Agent、SessionHeader、ContentBlockMap
type联合、交叉、映射、别名Phase、ToolExecutionResult、SessionId
class有运行时状态和方法的实现ReactLoopAgent、Session、LlmService

interface 和 type 大多只存在于编译期，构建后不会成为 JS 对象；class 则有 constructor/prototype。import type { Agent } 明确只导入类型，避免产生运行时依赖和循环加载；普通 import { BlockAssembler } 会保留为 JS import。

可辨识联合：先看 tag，再得到精确类型

type PreparedStep =
  | { kind: 'reject' }
  | { kind: 'enter'; messages: UserMessage[]; assembly: PromptAssembly }

if (decision.kind === 'reject') return false
// 这里 TS 已知道 decision.messages 和 decision.assembly 存在

DSH 对 phase、finish reason、tool preparation、approval result 等都用这种结构。tag 既是运行时数据，也是编译器的 narrowing 依据。闭合联合的 switch 在 default 调 assertNever(value)：若将来新增 variant，旧 switch 里的 value 就不再是 never，编译失败。可被插件声明合并扩展的联合则不能假装闭合，应保留 documented fallback。

证据：packages/core/agent-loop/src/agent.ts:38-52；packages/core/agent-loop/src/tool-calls.ts:171-195。

泛型让参数之间保持关系

若写成 append(type: string, data: object)，编译器不知道不同 type 要什么 payload。DSH 用泛型索引：

append<T extends SessionEventType>(
  type: T,
  data: SessionEventMap[T],
  ...opts: T extends SurfaceEventType ? [SurfaceIntent] : []
): SessionEvent<T>

T extends ... 不是 class inheritance，而是约束 T 必须来自事件名集合；SessionEventMap[T] 按 key 取对应 payload；条件类型决定 rest tuple 是必需一个还是空。调用 append('turn/start', {turn:1}) 可以，传 message payload 或 surface opts 都会报错。

runMaintenance<T>(task: ... => Promise<T>): Promise<T> 则把 callback 的结果类型原样传回，调用方无需 cast。

声明合并：插件如何扩展全局类型图

declare module 'cordis' {
  interface Context { agentLoop: AgentLoop }
  interface Events {
    'agent/pre-step'(...): Promise<PreStepDecision>
  }
}

declare module '@deepseek-ai/dsh-session' {
  interface SessionEventMap {
    'agent/inbox/spliced': { target: InboxTarget; ... }
  }
}

这叫 module augmentation。多个包对同名 interface 的字段会合并，所以安装新插件后，ctx.agentLoop、事件名/payload 和 Session event map 都得到静态类型，而核心包不用提前 import 所有插件。它非常适合 plugin ecosystem，但也意味着类型可见性依赖某个模块是否被 import；源码中的 import type {} from '@deepseek-ai/dsh-tools' 有时纯粹是为了让 augmentation 进入当前编译图。

证据：packages/core/agent-loop/src/index.ts:159-183；packages/core/agent/src/types.ts:141-304。

品牌类型：运行时都是 string，编译期不能串线

type SessionId = Branded<'SessionId'>
type CallId = Branded<'CallId'>

function SessionId(id: string): SessionId { return id as SessionId }

TypeScript 默认采用 structural typing：两个同结构的 string 别名会互相赋值。brand 加一个只在类型层可见的独特标记，让 SessionId 不能误传到 CallId。转换函数没有运行时验证或包装成本，所以它只表达“此边界已经认定该字符串具有此身份”；真正格式校验仍应在 parser/storage/wire 边界完成。

证据：packages/core/session/src/types.ts:1-26；packages/llm/llm/src/brand.ts。

可选属性、空值运算与条件 spread

const requestContext = {
  provider: config.provider,
  model: config.model,
  ...contextWindow === undefined ? {} : { contextWindow },
}

const cap = value ?? DEFAULT_CAP

?. 是 optional chaining；?? 只在 null/undefined 时取右侧，和 || 不同：0、空串、false 不会被当成缺省。条件 spread 在条件成立时加入字段，否则真的省略字段，满足 exact optional semantics，也让 JSON wire 不带无意义的 undefined。

异步：Promise、异步生成器与取消

async * stream(options): AsyncIterable<StreamChunk> {
  for await (const event of upstream) yield translate(event)
}

const fused = AbortSignal.any([caller, owner, factory])
signal.throwIfAborted()

async function 总返回 Promise；async * 返回异步迭代器，可以多次 yield。for await...of 每次消费一个异步元素。AbortSignal 不是 Promise cancellation 魔法：底层操作必须显式监听/传递它；DSH 在 await 后频繁 throwIfAborted()，防止已取消操作继续提交状态。

Promise.withResolvers<T>() 返回 {promise, resolve, reject}，适合 driver/lifecycle 的外部结算；Promise.allSettled 用于“所有资源都要排空，即使其中一个失败”。

using 与显式资源管理

using watchdog = idleWatchdog(signal, timeoutMs, 'LLM_STREAM_IDLE_TIMEOUT')
using preparation = SessionPreparation.create(session)

对象实现 Symbol.dispose 后，using 会在当前作用域离开时自动调用，类似 try/finally；异步资源可用 await using + Symbol.asyncDispose。DSH 用它确保 timer、watchdog、未发布 SessionPreparation 在成功、throw、cancel 路径都清理。

证据：packages/llm/llm-deepseek/src/adapter.ts:206-248；packages/core/agent-loop/src/index.ts:550-605。

静态类型不等于运行时验证

interface Config 只约束 TypeScript 调用者，YAML/JSON 进来时类型已擦除。因此 Service 常同时提供 static Config = z.object(...) 的 Schemastery schema；Session 又在 JSON 边界手工验证 lossless shape；API 用 TypeRT 生成 runtime registry。规则是：同进程 typed seam 信任 TS，配置、模型 JSON、持久化、worker、process、wire 边界做运行时验证。

阅读建议：遇到复杂类型先找 runtime tag 和真正消费点；遇到 as/! 则问“前面哪条 invariant 证明它安全”。DSH 的注释通常会明确指出这个证明，例如 scheduler 的 index 已受 loop bound 限制。
TypeScript 在 DSH 中的真正价值：它不只是给 JavaScript 加类型，而是把 event name→payload、provider→adapter、phase tag→可用字段、surface event→必需 metadata、opaque id→所属域这些协议关系做成可编译约束；运行时验证再守住静态系统无法覆盖的外部边界。
