③ 会话、事件投影与上下文治理

V1 的对象名没变，但底层已经从分散 JSON 迁到 SQLite + event projector；上下文则由 history filter、instructions 和 compaction 三条管线共同决定。

当前 V1 存储不是“每条消息一个 JSON”

Session.updateMessage() 与 updatePart() 不直接写表，而是发布 SessionV1.Event.MessageUpdated/PartUpdated。全局 SessionProjector 消费事件并 upsert message/part/session 表，同时维护 cost/token 汇总；读取则直接查询 Drizzle SQLite 表。

业务修改
  → EventV2Bridge.publish(V1 event)
  → EventV2 durable/event bus
  → SessionProjector
  → session / message / part / session_message / session_input tables
  → API list/messages/context 查询投影

packages/opencode/src/storage/storage.ts 仍有 JSON 文件锁与迁移代码，但不能再据此概括当前会话主存储。它的重要角色是把旧数据迁入数据库及承载尚未迁移的遗留资源。

证据：packages/opencode/src/session/session.ts:488-645；packages/core/src/session/projector.ts:211-458；opencode/src/storage/storage.ts:213-300。

消息模型：Message 和 Part 分离

用户/assistant 是 message；文本、reasoning、文件、tool state、step markers、compaction、subtask 等是 part。流式 delta 可以只更新某个 part 字段，UI 不必等待整条消息完成。工具 part 还保留 pending/running/completed/error、输入、输出、时间、附件、metadata 和 providerExecuted 信息。

MessageV2.toModelMessagesEffect() 才负责把丰富产品态降维为 provider 的 ModelMessage[]；filterCompacted() 为模型消费重新排序/隐藏历史。产品时间线和模型上下文不是同一个数组视图。

证据：packages/opencode/src/session/message-v2.ts:131-417,521-578；packages/core/src/v1/session.ts。

Instruction 注入分两级

阶段来源语义
每次模型请求的 system全局 AGENTS.md；可选 ~/.claude/CLAUDE.md；项目向上查找的第一类 instruction；配置 glob/URL文件并发读取、URL 限时拉取，组成 system parts
读文件时的局部发现目标文件到项目根之间的最近 AGENTS.md/CLAUDE.md/CONTEXT.md每个 assistant message claim 一次，并跳过 system 已注入或历史 read 已加载的文件

“第一类 instruction”有细节：项目层按文件名优先级寻找，找到一种后就不再把每个祖先的不同命名全部叠加；但同名文件的向上结果可以有多项。局部发现则随着 agent 实际读取子目录文件动态补充。

证据：packages/opencode/src/session/instruction.ts:60-169,179-223。

压缩不是简单 summarize-all

V1 有两个互补动作：

  • prune tool output：从后向前累计已完成工具输出；保护最近两 turn、最近 40k token、skill 输出和已有 summary 边界。真正超过 20k token 的可清理量才把旧结果标成 compacted。
  • 生成 compaction message：在可用上下文的 25%（默认夹在 2k～8k）预算内保留最近最多两 turn；更老 head 交给隐藏 compaction agent，总结时可带 previous summary，并记录 tail start。

overflow compaction 还会尝试把触发溢出的上一用户 turn 取出、先总结更旧历史，再 replay；这避免把一个本身很大的新任务硬塞进摘要。插件可通过 experimental.session.compacting 注入 context 或替换 prompt。

证据：packages/opencode/src/session/compaction.ts:28-185,204-323,325-440。

fork、child session 与 revert 是不同机制

机制做什么不做什么
fork创建新 session，并复制截止指定 message 的历史不让两个分支继续共享可变 transcript
TaskTool child用 parentID 建独立子 session，结果回流父 session不是同 session 内的角色标签
revertstage 目标、基于 snapshot 恢复文件，commit 后裁剪边界之后投影不等价于 Git commit/branch，也不保证任意外部副作用回滚

删除 parent 会递归删除 children，并尝试取消其 background jobs。V2 projector 在 revert commit 时会删除边界之后的 session_message 和 inbox 行，并 reset context epoch。

证据：packages/opencode/src/session/session.ts:598-629,693+；packages/core/src/session/projector.ts:396-453。

上下文的四种“真相”

完整审计事实：durable events
产品查询事实：SQLite projections
用户界面事实：message + parts 时间线
模型可见事实：filterCompacted → toModelMessages + system instructions

这四层刻意不同。比如旧 tool output 可以继续存在于事件与 UI metadata 中，但 model view 只看到清理标记；新的 instruction 文件能在后续 turn 注入，却不必伪装成用户消息。

判断：OpenCode 已从“保存聊天记录”走向“维护多种派生视图”。这为可靠恢复和多前端提供基础，也要求所有重放、revert、compaction 逻辑明确自己操作的是 event、projection、timeline 还是 model context。
