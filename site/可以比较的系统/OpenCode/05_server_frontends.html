⑤ Server-first 产品壳与扩展面

OpenCode 的 CLI 只是入口集合；真正稳定的产品形状是 HTTP/事件服务、目录或 Location scope，以及多个可替换客户端。

当前二进制入口

packages/opencode/src/index.ts 用 yargs 注册默认 TUI、run、serve、web、attach、ACP、MCP、models、agent、session、GitHub 等命令。无论本地还是远程，客户端都尽量复用 SDK/API：

模式server 位置客户端
默认 TUI可启动本地 listener/worker，也可连接外部 serverOpenTUI/Solid TUI
run默认 in-process fetch；--attach 走远程 HTTP非交互流式 renderer 或 mini interactive
serve独立 Node HTTP listener；默认 4096 回退随机端口任意 SDK/HTTP client
web同 headless server，并打开浏览器 appSolid Web App
acp复用 SDK session API实现 Agent Client Protocol 的 IDE/client
证据：packages/opencode/src/index.ts:33-141；cli/cmd/run.ts、tui.ts、serve.ts；acp/agent.ts:24-93。

Server 生命周期与请求 scope

server 基于 Effect HttpApi/NodeHttpServer。Server.Default() 提供无需 TCP 的 in-process fetch；listen() 才建真实 socket、WebSocket tracker、mDNS 和 scope finalizer。stop 可先停止发布，再关闭 active HTTP/WebSocket 连接与 scope。

服务启动不固定某个项目目录；请求经 directory/location middleware 映射到对应 InstanceState 或 Location services。于是一个 server 能服务多个项目，资源清理随 scoped cache/Location 生命周期发生。

证据：packages/opencode/src/server/server.ts:20-137,172-226；server/routes/instance/httpapi/middleware。

新 package 依赖方向

@opencode-ai/schema          纯协议/domain schemas
       ↓
core (domain/runtime)   protocol (HttpApi declarations)
       ↓                    ↓
       └──────── server (handlers + middleware)
                         ↓
client (generated fetch/effect clients；不得依赖 core/server)
                         ↓
sdk-next = client + core + server 的嵌入式组合
                         ↓
cli / tui / app / desktop

根 AGENTS.md 把这条依赖纪律写成硬约束：runtime dependencies 从 Schema 指向 Core/Protocol，再到 Server；Client 只能依赖 Schema/Protocol。它解决旧 packages/opencode 同时承载 domain、server、CLI、provider 和 UI glue 的耦合问题。

但迁移尚未结束：当前真正发布的 opencode bin 仍来自旧聚合包；新 @opencode-ai/cli 的 bin 名甚至还是 lildax。所以新依赖图是已落地的目标边界，不等于旧包已经退出。

前端：同一事件事实，不同呈现

  • TUI：packages/tui 抽出 OpenTUI/Solid runtime、session route、permission/question dialog、diff viewer、plugin slots；旧聚合包仍保留 CLI TUI glue。
  • Web App：packages/app 是最大源码包，负责多 session tabs、时间线投影、文件树/review、终端和设置；它不是简单把 TUI 搬到浏览器。
  • Desktop：packages/desktop 用 Tauri/native shell 包装 app，并处理更新、菜单、文件系统与平台集成。
  • Session UI：独立 packages/session-ui 把消息/tool/reasoning 的展示投影从具体前端拆出。
  • ACP：把 initialize/auth/session/prompt/cancel/fork/model/mode 映射到 SDK，适合 IDE 以标准协议嵌入。

MCP：客户端能力被物化为模型工具

OpenCode 可连接 local stdio 与 remote HTTP MCP server，管理 OAuth，并把 server tools 合入 ToolRegistry。资源能力则按连接状态动态增加 list_mcp_resources、list_mcp_resource_templates 和 read_mcp_resource；访问资源仍走 read permission，pattern 精确到 mcp:server:uri。

大文本统一截断；PDF/图片等支持的 blob 可变成 session attachments，并有 10 MiB 上限。这里的 MCP 是 OpenCode 作为 client 消费外部能力；ACP 是前端控制 OpenCode，方向不要混淆。

证据：packages/opencode/src/mcp/index.ts；session/tools.ts:27-39,136+；cli/cmd/mcp.ts。

插件：V1 任意代码 hooks，V2 scoped capability host

运行时模型关键语义
V1 plugin加载 internal/npm/local JS/TS，返回 Hooks可拿 SDK client、目录、worktree、Bun shell；hooks 顺序加载/顺序触发，支持 auth/provider/tool/message/compaction/event
V2 pluginPlugin.add(id, effect(host))每 plugin 独立 child Scope；同 ID 加载加锁，可替换/移除/等待，host 提供注册 capability
TUI feature pluginslots、commands、sidebar/system UI扩展呈现层，不与 server hook 假装是同一 API

V1 external plugin hook 按序执行，能修改工具参数/输出和模型消息，且 PluginInput.$ 可直接用 Bun shell。它是强扩展面，也意味着插件等同受信任代码。--pure 可禁用 external plugins，但默认 internal auth plugins 仍按 flags 加载。

V2 plugin host 用 Effect Scope 管理生命周期，并把 Agent、Catalog、Command、Integration、Reference、Skill 等注册能力集中到 host；这是更可组合的资源所有权模型，但与 V1 hooks 并存。

证据：packages/opencode/src/plugin/index.ts:65-123,125-306；packages/plugin/src/index.ts；packages/core/src/plugin.ts:23-167。

配置也是运行时组合层

配置会合并 global、项目、环境内容、远端 well-known 配置与插件来源；instructions 数组做去重拼接，普通字段 deep merge。JSONC 支持变量替换，远端配置做认证错误识别。每个目录的 Config/Agent/MCP/Plugin 等通过 InstanceState 或 Location layer 隔离，而 process-global 服务（database、events、execution coordinator）只保留真正全局的职责。

判断：OpenCode 的产品架构比 loop 本身更有辨识度：API server 是中心，目录/Location 是资源边界，TUI/Web/Desktop/ACP 是客户端，插件与 MCP 是两种不同信任级别的扩展面。
