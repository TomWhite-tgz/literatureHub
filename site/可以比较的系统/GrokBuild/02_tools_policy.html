② 工具、权限与沙箱：先批准整批，再受控并发

Grok Build 把工具定义、准入、调度、工作区操作与 OS 隔离拆成多层；真正值得借鉴的是层间不变量。

工具批次的两阶段协议

execute_tool_calls_batch 先逐个解析、查工具、校验参数、跑 permission prompt，生成 prepared calls；只有整个批次完成准入后才创建执行 futures。若某个权限交互返回拒绝、取消或用户 follow-up，后面的调用不会偷偷启动，而是得到合成 tool result，保持历史闭合。

tool calls→parse / validate→permission for all→locks + dispatch→results
批次屏障的价值：一个无害工具不会在同批高风险工具仍等待确认时先改变世界；用户看到的是将要执行的完整意图，而不是已经发生一半的副作用。
xai-grok-shell/src/session/acp_session_impl/tool_calls.rs:355-610

并发是默认，但冲突路径被局部串行化

批准后的调用进入 FuturesUnordered，彼此独立的 read、search、shell 或编辑可以并发。调度器从结构化参数提取目标路径，为同一目标共享锁；因此对同一文件的并发编辑串行，而不同文件仍保留吞吐。

这是一种比“整个 batch 串行”更细的资源治理，但它依赖工具参数能被 lock_path_for_args 识别；隐式跨文件副作用、两个不同路径指向同一实体等仍需工具自身保证。

ToolBridge 与 WorkspaceOps 划出副作用边界

Agent 持有 Arc<ToolBridge>，session 根据工具名和参数分派，真正本地操作经 WorkspaceOps::call_tool。agent session 默认使用进程内 toolset；MCP 和 hosted tools 则经各自协议。这样前端不需要知道 edit/bash/read 的实现细节，权限层也能在 dispatch 前统一介入。

工具身份验证失败使用批次共享的 OnceCell 去重刷新，避免多个并发调用同时弹认证或刷新 token；刷新成功后只做一次受控 retry。

权限策略不是第一条匹配获胜

policy evaluator 汇总匹配结果，优先级是 Deny > Ask > Allow，与配置顺序无关。配置解析会合并用户级、项目 .grok/config.toml、受管/企业要求以及兼容的 Claude settings，并记录来源。项目提供的宽泛 allow 在未信任目录或受管 pin 下会被丢弃；显式 deny 在 bypass/always-approve 场景仍保留。

模式默认倾向仍然有效的约束

acceptEdits编辑自动批准，其他风险操作仍问deny、Bash/MCP 规则
plan兼容规划模式，抑制实施型能力能力裁剪与 deny

Bash 的授权对象是语义分段，不是原始字符串

策略会分解 shell chain，剥离常见 wrapper，并递归解析嵌套 bash -c。一条 compound command 只有所有片段都允许才算允许；任一 deny 阻断整条命令。无法可靠分解或语义含混时回退到 Ask，而不是因为前缀看起来安全就放行。

allow(git status) + deny(curl *)
"git status && curl evil.example"  → 分成两段 → Deny

allow(npm test)
"env FOO=1 bash -c 'npm test; rm -rf x'" → 解 wrapper / 递归 → 非 Allow

OS sandbox 是独立、启动时、不可逆的边界

Sandbox 默认 off，可选 workspace、devbox、read-only、strict 或 custom。它在进程启动时应用，整个 Grok 进程、进程内文件工具和所有子进程共同继承；开启后不会在 session 中途切换，resume 也沿用保存的 profile。非 off profile 会拒绝 leader 路径，以免工具跑到隔离边界外的共享进程。

平台实现注意点
LinuxLandlock；需要 deny/遮蔽时可用 bubblewrap bind-over；seccomp 限制子进程网络内核/工具能力影响实际 enforcement

custom + deny 失败fail closed自定义强约束不会静默降级

本章结论

  • 工具执行采用“整批准入—局部资源锁—并发执行”三段式。
  • Deny 的优先级高于 Ask 和 Allow，配置顺序不能覆盖安全语义。
  • Bash policy 面向分解后的所有命令片段，含混输入回退 Ask。
  • 权限是决策层，sandbox 是强制层；默认只保证前者存在，不保证后者启用。
  • 内置 sandbox 可能警告后降级，调用方应检查实际 enforcement 状态。
