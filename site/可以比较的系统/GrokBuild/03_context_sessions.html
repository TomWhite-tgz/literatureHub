③ 上下文与会话：actor 管热状态，JSONL 管耐久事实

Grok Build 没把 conversation 塞进 SessionActor 的大锁，而是用专门 actor 串行化突变，再用异步 persistence actor 把事件写到磁盘。

ChatStateActor 是单一可变状态所有者

ChatState 保存 conversation、sampling config、prompt index、累计 token、agent 编辑路径、上次 compaction 位置、credentials、usage、turn capture 与 harness trace。外界只通过 ChatStateHandle 发 command；需要顺序确认的操作带 oneshot ack，纯通知可 fire-and-forget。

并发模型：把“谁能改对话”变成消息顺序问题，而不是让采样、工具、UI、持久化同时争抢一把锁。SessionActor 可以 await 网络与工具，但聊天状态突变仍由一个 actor 排队。

构造 API 请求时做三类修复

  1. tool pairing repair：清理悬空 tool call/result，避免供应商因历史不合法持续返回 400。
  2. 旧工具结果裁剪：上下文利用率超过阈值时，在请求副本中清空久远大结果；最近 turn 保留。更老的内存历史也可 eager hard-clear，以控制长会话常驻内存。
  3. memory/reminder 注入：按策略把跨 turn 状态放入请求，但不破坏稳定前缀。

默认 pruning gate 使用 token 估算与 context window：测试明确覆盖 50% 不触发、60% 触发。它不仅追求“塞得下”，还维护 prompt cache 友好的 prefix stability。

图片按真实 wire bytes 受控淘汰

请求代理有 50 MB body 上限。request builder 不用 token 近似图片大小，而是计算序列化后 body bytes；在上限前预留 3 MB headroom，触发后从最旧 inline images 开始用文本占位替换，并通过 hysteresis 回收约一半空间，避免每次请求在阈值附近抖动。

设计细节：图片淘汰只发生在需要的请求副本上，并维持稳定前缀；小图片不会因为 token compaction 被无谓删除。

Compaction 是共享引擎，不是一段 summary prompt

xai-grok-compaction 单独成 crate，包含 intra/inter compaction、代码内容处理、history validation 与分步执行。session 在采样前做 overflow preflight，压缩时保存 checkpoint/request，并把 todo、运行中后台任务、子 Agent、artifact、编辑状态等纳入摘要上下文；完成后以受控 replacement 更新 ChatState。

因此 compaction 的产物不是一段脱离现场的聊天摘要，而是恢复继续工作的状态包。turn capture 还记录压缩前后的消息，让 goal planner/verifier 的证据不会因普通 rewind 或裁剪无声丢失。

PersistenceActor 把展示流和模型历史分开

持久化 actor 接收 session updates 与 chat items，合并高频 ACP text chunks，随后写入适配器。xAI 原生 chat items 可直接保存；UI 更新、聊天历史和 summary 分文件，避免为了恢复模型上下文而重放所有渲染细节。显式 flush/durable append 用于关键 commit point。

目录结构把独立恢复域显式化：子 Agent 保存在父会话目录下；workflow 有自己的 journal；compaction checkpoint 不混入展示事件。fork 会复制选定 checkpoint 并截断新分支，代码专门避免追随 symlink；跨目录 relocation 通过 journal 恢复中断搬迁。

JSONL 写入专门考虑 torn tail

append 前会检查旧文件末尾是否完整换行；若上次崩溃留下半条记录，先补换行，把损坏限制在恰好一行，再追加新记录。读取器跳过无法解析的行。durable 路径不仅 sync_all 文件，也同步父目录，提升断电后目录项可见性。

恢复哲学：不假设每次写入原子，也不因为一条坏记录放弃整个会话；让损坏局部化、可跳过，并把关键状态放在可单独校验的文件中。

本章结论

  • 热状态用 actor 串行化，磁盘状态用独立 persistence actor 异步落盘。
  • 请求构造会修复 tool pairing，并按 token 与真实 body bytes 分别治理文本和图片。
  • Compaction 保存任务现场与运行中资源，不只是聊天摘要。
  • 会话目录按数据用途拆分，支持 resume、fork、rewind、relocation 与子会话。
  • JSONL 采用 torn-tail healing、容错读取和 durable sync，把崩溃损坏限制在局部。
