先说结论

Grok Build 的核心不是 xai-grok-agent::Agent，而是 xai-grok-shell 中的 session actor。Agent 是近乎不可变的 prompt、tool bridge 和策略包；SessionActor::process_conversation_turn 才负责采样、流事件、工具调用、恢复、压缩与终止。工具批次先统一完成准入，再用 FuturesUnordered 并发执行；会话可变状态另交给单线程 ChatStateActor 串行持有。

一句话架构：xai-grok-pager-bin 分流 TUI、headless、ACP 与 leader；它们汇入同一个 shell/session 内核；session 通过 sampler 调模型、通过 workspace/tool bridge 执行工具、通过 chat-state actor 管对话，并把 UI 更新与聊天记录写入可恢复的 JSONL 存储。
