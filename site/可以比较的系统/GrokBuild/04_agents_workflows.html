④ 子 Agent 与工作流：随机探索与确定性编排并存

子 Agent 负责有独立上下文的模型工作；workflow 用受限 Rhai 和可重放 journal 负责长流程。二者是互补层，不是同一个概念的两种叫法。

子 Agent 是独立 session，不是 prompt 宏

内置类型包括 general-purpose、explore 和 plan。每个子 Agent 有自己的 conversation、session storage、模型/effort 解析和工具集；父会话只获得其状态与最终结果，不把完整子对话灌回主上下文。子会话目录嵌套在父 session 的 subagents/{id} 下。

最大深度固定为 1：只有顶层会话可 spawn，子 Agent 再调用会得到 depth-limit error。这主动放弃任意树形自治，换取成本、并发与取消传播更容易推理。

能力、角色与 persona 分三层解析

层决定什么例子
Agent type基础 session 定义与默认工具explore/plan 不编辑；general-purpose 全能力
capability mode对子工具集做粗粒度上限read-only、read-write、execute、all
persona / role行为指令、model、effort、默认 isolation、输入/输出契约researcher、reviewer，或项目自定义角色

Persona 在 resolution 阶段叠加，不由主模型在 spawn_subagent 参数中任意指定。找不到、没有 instructions 或指令文件不可读会拒绝 spawn。输入/输出契约让多个 persona 能通过 artifact 串接，而不必共享整段自然语言 transcript。

xai-grok-pager/docs/user-guide/16-subagents.md:72-137, 162-174

执行可阻塞、后台、续接或隔离

  • blocking：父 loop 等待 child 完成并直接拿结果。
  • background：立即返回 subagent id，稍后用统一输出工具查询；TUI tasks pane 持续显示状态。
  • resume_from：新 child 续接一个已完成 child 的完整上下文，适合研究后实施。
  • cwd：在指定目录共享工作区。
  • isolation: worktree：创建独立 Git worktree，结果携带路径，再通过 x.ai/git/worktree/* apply。

MCP server 默认继承父会话已经连接的集合，但 agent frontmatter 可选 all、none、named 或 except。这里继承的是已建立能力，不是重新执行一遍未知项目配置。

后台任务是通用生命周期，不只服务子 Agent

Shell command、monitor 和 subagent 都可以作为后台任务出现在统一 registry。调用方可 get output、wait any/all（一次最多 20 个）或 kill；前台命令可用 Ctrl+B 转后台。/loop 与 scheduler 提供 session 内唤醒，循环有次数和最长持续时间上限，避免无界 cron。

Goal loop 给开放任务加一层完成治理

xai-grok-shell/session 中 goal planner、classifier、evaluator、strategist、stop detector、summarizer 与 tracker 组成独立编排。完成分类器要求用真实 entrypoint、行为测试、文件状态或外部可观察证据验证目标；它不把“模型声称完成”直接当作完成。

这套 goal loop 仍是模型驱动的，所以适合开放式目标判断；需要严格可恢复控制流时，源码提供了另一条路径：workflow。

xai-grok-shell/src/session/goal_classifier.rs；goal_evaluator.rs；goal_orchestrator.rs；goal_tracker.rs

Workflow：受限 Rhai 脚本编排 Agent 调用

xai-workflow 运行确定性 Rhai 脚本。引擎禁用 wall-clock time、随机数、sleep 与 process exit；脚本只能通过显式 host API spawn/resume agent、等待、验证或暂停。默认 agent-call budget 为 128，最大 1,024，host calls 上限 10,000，phase 与名称也有边界。

Outcome意义
Completed脚本与验证完成
Paused因用户、backoff、no-progress、verification 或 infrastructure 等原因可恢复暂停
BudgetExceeded在新调用前阻断，不继续消耗
Cancelled / Failed显式终止，保留 journal 供诊断

Journal 让恢复等价于重放，而不是猜测

每次 host call 写入稠密递增 seq、调用 kind、request hash 与结果。恢复时脚本从头运行：若下一次 host call 与 journal 的 kind/hash 相同，就直接返回已记录结果，不再次执行副作用；不同则报 Divergence，说明脚本或输入发生变化。

第一次：agent_call(req A) → 真执行 → journal[0] = hash(A), result R
恢复时：agent_call(req A) → hash 相同 → replay R
修改后：agent_call(req B) → hash 不同 → Divergence（拒绝冒充同一次运行）

Journal 最大 64 MB，加载有条目/字节上限；会截断 torn tail，拒绝 symlink，并以 no-follow 方式打开。它把“耐久性”落实在 host-call 边界，而不是依赖模型重新阅读摘要猜测做到哪一步。

本章结论

  • 子 Agent 用独立 session 隔离上下文，树深固定为一以限制失控自治。
  • 能力模式、agent type 与 persona/role 分离，工具上限和行为风格可分别治理。
  • worktree isolation 与 resume_from 分别解决写冲突和多阶段连续性。
  • Goal loop 解决开放式完成判断，workflow 解决确定性长流程。
  • 基于请求 hash 的 journal replay 是 Grok Build 最适合长期任务的设计之一。
