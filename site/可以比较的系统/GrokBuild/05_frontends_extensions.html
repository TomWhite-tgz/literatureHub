⑤ 前端与扩展：ACP 是内部接缝，不只是 IDE 插件协议

TUI、无头模式、stdio/WebSocket agent 与共享 leader 最终消费同一类 session updates；扩展则经过来源、信任与能力治理。

四种消费形态，共用一个运行时

TUI 自己也走 ACP 形态的 typed channel

xai-grok-pager/src/acp/mod.rs 可以连接进程内 agent 或 leader，并向 UI 返回相同的 ACP tx/rx。进程内模式通过 simplex streams 启动 MvpAgent 与 AgentSideConnection，leader 则把这条连接远程化。

架构意义：ACP 不是最后贴上的 IDE adapter，而是 UI 与 runtime 的内部协议接缝。前端切换不会复制 session loop，测试也能在同一事件面模拟 client。

标准 ACP 之外还有 x.ai/* 扩展

Agent mode 实现标准 session/prompt/cancel、流式回复、tool update 和 permission，同时用 x.ai/* 扩展暴露文件系统、Git/worktree、terminal、session fork、rewind 等 Grok 特性。WebSocket server 支持连接断开后重连到仍存活的会话。

这保持了互操作底座，同时承认 coding agent 的 diff、终端和 worktree 能力超出最小 ACP。代价是第三方客户端若只实现标准面，会得到可用但不完整的体验。

Skills 与 project rules：按需进入上下文

Skills 提供名称、描述和指令资源，模型先看到目录信息，需要时再激活正文，避免所有领域说明常驻 system prompt。项目规则与 memory 提供仓库级和跨会话上下文；它们有发现优先级、容量和注入策略，不等同于任意文件自动成为指令。

xai-grok-pager/docs/user-guide/08-skills.md；12-project-rules.md；13-memory.md；xai-grok-tools/src/implementations/skills/

Plugin 是分发容器，不是新的执行内核

Plugin 可捆绑 skills、commands、agents/personas、hooks 与 MCP 配置。加载器解析来源与优先级，把每类资源送回原有子系统；所以安装一个 plugin 不会绕过 tool permission、folder trust 或 hook 生命周期。用户可在 extensions UI 查看来源和状态。

这比允许 plugin 注入任意 Rust 代码保守：扩展表达力来自声明式资源、外部命令/MCP 和既有 host contracts，故障与信任边界更清楚。

xai-grok-pager/docs/user-guide/09-plugins.md；xai-grok-agent/src/plugins/；xai-grok-plugin-marketplace；xai-grok-pager/src/views/extensions_modal.rs

MCP 是动态能力面，并带继承与信任规则

MCP servers 可来自用户配置、项目或 plugin，支持 stdio/HTTP 等连接。工具定义在 turn 采样前解析：配置可选择阻塞等待或 progressive loading。项目级 MCP/LSP 与 hooks 共用 folder-trust store；未信任项目不能仅靠仓库文件启动本地代码。

子 Agent 默认继承父会话已连接 MCP，但 frontmatter 可限制。权限系统还支持按 server 或精确 tool 记住 allow，避免把某一工具许可无意扩大为整个生态。

xai-grok-pager/docs/user-guide/07-mcp-servers.md；xai-grok-mcp/src/servers.rs；xai-grok-shell/src/session/acp_session_impl/sampler_turn.rs

Hooks 能阻断，也明确规定失败语义

PreToolUse 可显式 deny，PostToolUse 记录/同步，SessionStart 注入环境，Stop/SubagentStop 可让模型继续直到验证成立。来源包括用户、项目、兼容配置、plugin 与受管配置；多层是 additive，重复项按权威来源去重，并在 UI 显示 provenance。

项目 hooks 需要 folder trust。hook timeout、崩溃、无效输出默认 fail-open，只有显式 deny 阻断；Stop gate 最多连续推动 8 次，防止验证脚本把 turn 永久锁死。对强安全要求而言，hook 不能替代 policy deny 或 sandbox。

xai-grok-pager/docs/user-guide/10-hooks.md:9-80, 152-166, 209-264；xai-grok-hooks

本章结论

  • TUI、headless、ACP 和 leader 共用 session 内核，ACP 也是内部 UI/runtime 接缝。
  • x.ai/* 在标准协议之上补足 coding-agent 特性，互操作与完整体验分层。
  • Skills 按需披露；plugins 主要是声明式资源分发容器。
  • 项目 MCP/LSP/hooks 共用 folder trust，但关闭这道机制会一起解除门禁。
  • Hook failures 默认 fail-open，因此安全拒绝必须落在 policy 或 sandbox。
