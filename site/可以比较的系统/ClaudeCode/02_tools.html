② 工具、权限与沙箱：三层安全语义

工具先声明能力，编排器决定并发，执行管线再做 schema、hook、permission 与结果闭合；sandbox 是其后的可配置执行边界。

Tool 接口把“能否并发”做到输入级

契约语义
inputSchema / validateInput结构验证与领域验证分开
isConcurrencySafe(input)同一工具可因不同参数有不同并发性
isReadOnly(input)读写性质也由实际操作决定
checkPermissions(...)工具自身给出规则判断，再汇入通用 permission system
maxResultSizeChars工具结果进入上下文前有独立上限

缺省值刻意保守：未知并发性视为 false、未知读写视为写；这样新增工具不会因忘记声明就获得并发写权限。通用 permission 默认仍会继续裁决，不等于无条件放行。

批执行：并发 IO，顺序语义

runTools() 将连续的 concurrency-safe 工具组成批次，非安全工具单独串行；默认最大并发 10，可由 CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY 调整。流式执行器进一步允许安全工具在模型输出尚未结束时开跑。

完成顺序可乱

Read A、Grep B、WebFetch C 可以物理并行，progress 消息即时释放。

可见顺序不乱

最终 results 按 tool block 顺序缓冲；遇到 executing 的排他工具时停止越过。

Bash 的错误会取消并行 sibling（代码认为 shell 命令常有隐式依赖链），普通 Read/WebFetch 失败不会株连。fallback、用户打断或 sibling error 都会造 synthetic result；discard 则确保旧模型分支的真实结果不再进入对话。

执行管线

tool_use block
  → Zod safeParse → validateInput
  → speculative Bash classifier（与 hooks 准备重叠）
  → backfill observable clone
  → PreToolUse hooks（可改输入/阻止/给 permission）
  → tool.checkPermissions + canUseTool
  → tool.call(original model input)
  → map result + size budget
  → PostToolUse / PostToolUseFailure
  → context modifier
微妙但重要：backfillObservableInput 只修改给 hook 与权限观察的 clone，实际调用和 transcript 继续使用模型原始输入。这避免 UI 补全字段改变 VCR/hash/序列化身份，是一种“可观察视图”和“事实记录”分离。

权限是带 provenance 的竞态

规则层先返回 allow / deny / ask；若为 ask，不同运行角色进入不同 handler。

角色自动路径人工路径
主交互 agentpermission hooks、Bash classifier 在后台竞态本地 dialog；也可与 claude.ai bridge、Telegram/iMessage 等 channel response 竞态
Coordinator先 hook，再 classifier无结果才下沉
Swarm worker先 classifier通过 mailbox 把请求转给 leader

决策携带 rule、hook、classifier、mode、sandboxOverride、workingDir 等原因；配置来源覆盖 policy/project/user/session/CLI。它既用于解释 UI，也用于遥测和持久化 permission update。

Sandbox：adapter 可证，runtime 不可证

沙箱默认由 settings 的 sandbox.enabled ?? false 控制，并非始终开启。adapter 将 WebFetch/permission rules 与 sandbox settings 编译成 network domain、filesystem allow/deny 和 socket 策略；默认 autoAllowBashIfSandboxed=true、allowUnsandboxedCommands=true，另有 unavailable/fail 配置和平台检查。

外部依赖底层隔离由 @anthropic-ai/sandbox-runtime 提供。本树能看到初始化、更新、wrap 和配置生成，不能审计其 namespace/seccomp 等低层实现。与本地 Codex Rust 源码能直接看到 bubblewrap/Seatbelt/Windows 实现的证据强度不同。
