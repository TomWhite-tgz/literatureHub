⑥ Claude Code 的优点与 AutoResearch 借鉴

先用同口径源码比较定位优势，再把 Claude Code 可迁移的机制落实到 AutoResearch 的状态与实现顺序。

结论先行

Claude Code 的强项：在单个长会话内部，把流式工具并发、权限竞态、上下文减重、后台 agent 与可恢复 transcript 做得极细。
Codex 的强项：把 thread/turn/event、执行治理和多前端 JSON-RPC 边界做成更硬、更独立的 Rust 组件。
Pi 的强项：用极小 Agent loop、provider/message 投影和任意代码扩展组成可嵌入栈；但下一代 durable Harness 的执行主链尚未完成。
AutoResearch 最佳组合：Pi 式小 loop 作内核，Codex 式 run/event/治理作骨架，Claude Code 式 context/task/session 语义填充长期自主运行。

Claude Code 真正值得抄的五件事

  1. 并发执行不牺牲上下文确定性。科研搜索/评估可乱序完成，但进入 reasoning context 与 provenance log 必须稳定排序。
  2. 恢复对象大于 messages。还要恢复裁剪决策、工作目录、工具池、权限、预算、后台任务与缓存前缀。
  3. 压缩产物是结构化恢复包。summary 之外保留 tail、文件、计划、skill 与任务状态。
  4. 权限必须带来源。“允许”要回答由 policy、guardian、用户、sandbox 还是 worker leader 允许。
  5. 后台任务必须有稳定 ID、独立日志与可继续入口。否则只是不可审计的 fire-and-forget coroutine。

建议的最小状态机

ResearchRun
  accepted → planning → running
                       ├─ waiting_permission
                       ├─ waiting_dependency
                       ├─ compacting
                       ├─ interrupted → resumable
                       └─ evaluating → completed | failed

ResearchTask
  pending → claimed → in_progress → completed
                    └─ blocked / stopped → resumable

每一次状态变化只追加事件；当前状态由 fold 得出。大文本与实验输出落 artifact store，事件只保留 hash/ref/preview。context projector 根据预算选择事件与 artifact preview，checkpoint 不能替换原始证据链。

不建议现在照搬的复杂度

  • 不要一开始同时实现 in-process、tmux、remote 三种 worker backend；先让一个 task state machine 可恢复。
  • 不要在只有一个 UI 时预付完整 JSON-RPC/app-server 版本兼容成本；先稳定内部 event schema。
  • 不要依赖模型摘要作为唯一事实源；科研结果必须回指 dataset/code/env/seed 和原始 artifact。
  • 不要把 feature gate 的存在当成功能完成；缺失实现必须在 capability registry 中显示 unavailable。
  • 不要让权限 UI 与 policy engine 相互递归；先定义纯函数 decision 与 provenance，再加各种人工 channel。

一个可执行的实现顺序

  1. 先建立 RunEvent、ActionAttempt 与 artifact content-addressing。
  2. 让单 agent 在进程中支持 interrupt/resume，并验证 crash 后 tool pairing 不破坏。
  3. 加入 ContextCheckpoint，从 tool-result preview 与 preserved tail 开始，不先做复杂摘要树。
  4. 引入一个 background task backend、稳定 task_id 与独立 transcript。
  5. 最后再加 policy provenance、worktree/container isolation 和远程 transport。
最终判断：Claude Code 给 AutoResearch 的最大启发不是“多开几个 agent”，而是把长程自治中最容易丢失的东西——分支、权限来源、上下文损耗、后台任务身份和工作区——全部变成可持久化、可恢复、可解释的状态。
