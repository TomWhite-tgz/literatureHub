④ 子 Agent 与团队：任务不是 Promise，而是可恢复实体

AgentTool 统一启动 specialized agent、background task、fork、resume 与 worktree；swarm 再把单个子 agent 扩展为有 mailbox 和 leader 的团队。

runAgent 创建的不是“另一次 query”那么简单

选择 definition/model/tools→创建稳定 agentId→派生 permission/context→SubagentStart hook→写 sidechain transcript→query loop

同步 agent 共享父 abort controller；异步 agent 默认拿独立 controller，从而在父 turn 结束后继续。子 agent 可获得 agent-specific MCP server；只清理本次新建 client，不关闭父级共享连接。read-only 的 Explore/Plan 还可精简 CLAUDE.md 上的写入规则。

Fork：继承上下文，同时优化缓存

fork path 继承父 system prompt、工具池和对话前缀。若同一 assistant message 里并发产生多个 fork tool use，它会保留完整 assistant block，并为所有 tool use 填入字节相同的 placeholder result，只有最后的 child directive 不同。这让多个 child 最大化共享 prompt-cache prefix。

这是很少见的组合设计：“多 agent 分叉语义”与“缓存键字节稳定性”在同一个构造函数中被共同维护。fork child 虽保留 Agent tool 以维持工具 schema 相同，但通过 boilerplate tag 在运行时禁止递归 fork。
src/tools/AgentTool/forkSubagent.ts:19-32, 74-107, 107-183

Worktree：隔离写入，不等于自动合并

AgentTool 可创建 worktree 并在 child prompt 中解释父 cwd 与新 cwd 的路径映射。结束时，若 worktree 无改动可自动清理；有改动则保留路径/branch 交给后续处理。metadata 会保存 worktreePath，resume 时检查目录是否仍存在，并刷新 mtime 防止刚恢复的 worktree 被陈旧清理任务删除。

AgentTool.tsx:579-683；forkSubagent.ts:201-209；resumeAgent.ts:64-96, 192-255

Resume：恢复的不只是消息

resumeAgentBackground() 加载 agent transcript 与 sidecar metadata，过滤孤立 thinking / 未闭合 tool use，重建 tool-result replacement state，恢复 agent definition、父 system prompt（fork）、cwd 与 permission context，再用原 agentId 注册新 background lifecycle。

恢复对象原因
消息链继续语义上下文
replacement state防止被裁剪的大工具结果在恢复后重复/漂移
worktree cwd文件操作必须落在原隔离工作区
agent type + rendered prompt维持工具/提示语义和 fork cache prefix

Swarm：在 agent 之上再加控制平面

团队 worker 可运行 in-process，也可落到 tmux/iTerm pane backend。任务表有 owner、blockedBy 与 claim/update；空闲 worker 会领取无依赖的 pending task。权限请求通过 mailbox 发给 leader，response 再回 worker；shutdown、message、idle notification 也复用 mailbox。

复杂度提醒：这里同时存在 AgentTool background task、in-process teammate、pane/process teammate、remote agent 和 coordinator mode。它们复用部分 Task/UI/permission 抽象，却不是完全统一的一种 worker。AutoResearch 应先统一 task state machine，再决定是否需要多 backend。
