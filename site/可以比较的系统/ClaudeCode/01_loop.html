① Agent loop：流式状态机，而非 ask/answer

query() 是 async generator；它既吐模型事件，也吐工具进度、持久消息、tombstone 和压缩边界，最后返回终态。

主链

QueryEngine.submitMessage / REPL
  └─ query(params): AsyncGenerator
      └─ while (true)
          ├─ memory + skill prefetch
          ├─ project API view / compact
          ├─ call model stream
          │   └─ tool_use block arrives → StreamingToolExecutor.addTool()
          ├─ finish / fallback / recovery
          ├─ drain tool results in valid order
          └─ state = {..., transition: next_turn} → loop
src/query.ts:181-238, 307-328, 563, 1382, 1718-1728

显式 State 与 Continue reason

跨迭代变量集中在 State：消息、工具上下文、auto-compact 跟踪、max-output 恢复次数、reactive-compact guard、turn 数和上一跳 transition。各个 continue 不是裸跳转，而会写入 reactive_compact_retry、max_output_tokens_escalate、stop_hook_blocking、token_budget_continuation 或 next_turn。这使恢复路径可被测试直接断言。

阶段关键行为为什么重要
进入迭代memory prefetch 每个用户 turn 一次；skill discovery 每轮一次，并与采样/工具重叠把慢发现藏在关键路径之外
模型流观察到 tool block 就算存在后续工具；明确不信任 stop_reason === tool_use事实来源是实际内容块，不是易错元数据
流式回退tombstone 旧的 partial assistant；discard 已启动工具；去掉与模型绑定的 thinking signature失败分支不污染新模型上下文
错误闭合为未配对 tool use 生成 synthetic tool result下一次 API 请求保持协议有效
停止无 tool use 时仍可能被 Stop hook 或 token budget 要求继续“模型结束”不等于“系统完成”

工具执行与模型采样发生重叠

传统循环等完整 assistant message 后才执行全部工具。这里的 StreamingToolExecutor 在 tool block 完成时立刻入队：并发安全的工具可一起跑，不安全工具成为排他屏障；进度可马上 yield，最终结果仍按接收顺序释放。

亮点：这是 latency hiding，不是放弃确定性。系统允许“物理完成顺序”变化，但不允许“模型看到的结果序”随调度随机变化。

恢复阶梯

正常采样→collapse drain→reactive compact→max-output 升级/截断→显式终态

Prompt-too-long、media-size 与 max-output 错误会先被“withhold”，直到系统知道是否有可恢复路径。内部 collapse/reactive 实现缺失，但 query.ts:800-816, 1067-1245 能完整证明恢复顺序。若 feature 被编译掉，代码还处理“错误被 collapse 拦下但无恢复模块”的退路。

仅接口可见不能从调用点推断 collapse 的摘要算法或阈值；能确认的是它优先于更重的 reactive compact，并以保留 granular context 为目标。

QueryEngine 并非全系统唯一内核

QueryEngine 负责 headless/SDK 会话，每个 conversation 一个实例，每次 submitMessage() 开启一 turn。它会在进入 query 前先落 user message，使进程在采样前退出仍可恢复。但源码注释写的是“used by headless/SDK and (in a future phase) REPL”，所以 REPL 仍有自己的 UI 历史和状态投影，不能宣称 Claude Code 已完全统一到单一 session kernel。
