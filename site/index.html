🧭 选题讨论 · Agentic Literature Search 综述可行性

与 alphaXiv 的交流 · 2026-08-03
点开阅读 ▾

问题：写一篇 agentic literature search 的综述，能不能发顶会？下面按讨论脉络折叠存档，含四类做法的具体实现步骤。

总判断：单纯"工作汇总"式综述发顶会概率不高；做成 统一问题定义 + 系统分类 + 可复现实验 + 新 benchmark/评测协议，机会明显提高。
  • 领域最突出的事实：专门的科学文献搜索 benchmark 上顶级模型表现仍然很低 —— AutoResearchBench 最佳 Deep Research 准确率仅 9.39%，Wide Research 最佳 IoU 仅 9.31%。
  • 竞争力排序：普通综述 较低 → 综述+统一复现 中等 → 综述+新 benchmark 高 → 综述+benchmark+新方法 最高（工作量最大）
  • 推荐路线：benchmark-driven survey；切入点 Evidence-grounded & completeness-aware agentic literature search（找对、找全、找到精确证据、明确无法确认之处）。
① 这个方向目前有哪些工作 —— 四条线，不要混在一起Agentic RAG / Survey 生成 / ResearchArena / 专门 benchmark
线 1 · 通用 Agentic RAG / Deep Research 框架

讨论 agent 如何动态决定：要不要检索、去哪个数据库/网页检索、如何改写 query、是否继续搜索、如何验证证据、如何综合多来源、是否多 agent 协作。代表：Agentic Retrieval-Augmented Generation: A Survey on Agentic RAG —— 从 agent 数量、控制结构、自主性、知识表示等维度整理，并明确指出传统 output-level 指标不足以评估 agentic 系统，还需考察搜索轨迹、规划深度、工具调用、适应性和成本。但范围较宽（覆盖医疗/金融/企业文档），不专门聚焦学术文献搜索。

线 2 · 自动文献综述与 survey generation

目标：给定主题，自动找论文、构造 taxonomy/outline、生成带引用的 survey。代表工作：AutoSurvey；SurveyForge（用已有 survey 结构 + outline database 生成层级大纲，Scholar Navigation Agent 做 query decomposition、memory-based retrieval、temporal-aware reranking，并行生成各小节）；SurveyBench（从"生成流畅长文"转向评估 coverage、structure、depth、citation、quiz answerability）；Agentic AutoSurvey；Agentic AI-Empowered Dynamic Survey Framework。

局限：它们把搜索当作写作流水线中的一个模块，指标是最终 survey 质量，不独立评估：搜索是否全面、是否找到关键论文、条件判断是否正确、何时可以停止、是否遗漏反例或相邻方向、搜索是否高效。

线 3 · 学术研究 agent 的搜索、筛选和组织能力

ResearchArena（较早且重要）：把研究前期拆成 information discovery / selection / organization 三步，基于约 1,200 万篇全文论文和约 7,900 篇 survey 构建离线环境。重要结论：在文献发现和筛选任务上，LLM agent 并没有稳定超过简单的 keyword/title retrieval —— STORM、SELF-RAG 等 agent baseline 在 discovery/selection 上表现反而较弱。"能做多轮推理"并不自动意味着"能做高质量文献搜索"。

线 4 · 专门的 scientific literature discovery benchmark

AutoResearchBench（当前特别值得关注）定义两类任务：Deep Research —— 根据分散在全文、附录、图表、引用关系中的线索找到唯一目标论文，或判断不存在；Wide Research —— 找出满足一组复杂科学约束的完整论文集合。要求处理隐藏合取条件、全文证据、citation chain、集合完整性和 abstention，不是普通 topic retrieval。

它揭示的失败模式：找到候选后无法精确验证约束、无法排除边界案例、不能综合分散在全文中的证据、Wide Research 中无法保证召回完整、搜索过早停止或反复搜索相同内容。

同线近期工作：ScholarQuest（taxonomy-guided academic paper search，本页 Benchmark 板块已深读归档）、Multi-Turn Agentic Scientific Literature Search via Workflow Induction（即本页已深读的 PaperPilot）、S1-DeepResearch、SciResearcher。研究重点正在从"LLM 能不能写出一篇 survey"转向"agent 能不能在大型、动态、全文级科学语料库中，可靠、完整、可验证地完成研究搜索"。

③ 纯综述为什么难发顶会 + 三个更有机会的形态（A 复现 / B benchmark / C taxonomy）

纯综述（搜集已有工作、按单 agent/多 agent/tool use 分类、总结优缺点和未来方向）很可能被评为：taxonomy 主观、文献边界不清、与已有 Agentic RAG survey / Agentic LLM survey / 自动 survey generation 工作重叠、缺少新的 empirical insight、缺少可复现实验或数据资源。已有 Agentic Large Language Models, a survey（Reasoning–Acting–Interacting 视角）和 Agentic RAG Survey（架构分类）——换一种方式重新整理，创新性不足。

方向 A · 系统综述 + 大规模实证复现 中等潜力

不只总结别人做了什么，而是统一复现一批系统：keyword/BM25、dense retrieval、citation graph traversal、query decomposition、ReAct agent、Self-RAG、multi-agent search、Deep Research 类系统、survey-generation pipeline。在同一 corpus、同一组 topic、同一套预算下比较：Recall@k、Precision@k、nDCG、citation coverage、evidence correctness、answer completeness、search cost、latency、tool-call efficiency、stopping quality、calibration、abstention quality。这就不再只是 survey，而是 systematic empirical study —— 对 SIGIR、ACL、EMNLP、NeurIPS D&B、COLM 比纯 narrative survey 更有说服力。

方向 B · 提出新的 benchmark 最有机会

现有 benchmark 的空缺：ResearchArena 不重点评估最终 QA 和全文证据链；SurveyBench 不完全等于动态 search agent benchmark；AutoResearchBench 主要覆盖 CS 和固定语料库，作者自己指出跨学科、动态语料、多模态证据、calibration、abstention 仍待研究。

一个更完整的 benchmark 可以同时评估：single-hop QA（一篇论文找事实）、multi-hop QA（跨论文比较方法和结果）、literature discovery、systematic filtering（按方法/数据集/年份/实验条件筛选）、citation verification（claim 是否被论文支持）、contradiction detection（论文间冲突）、evidence sufficiency、completeness（是否漏掉关键工作）、temporal robustness（面对新论文是否仍有效）、interactive search（用户逐轮澄清意图）、stop/abstain（何时说"目前无法确认"）。若有高质量人工标注、开放 corpus、统一 tool interface、可复现 baseline 和误差分析，本身就是很强的贡献。

方向 C · 统一 taxonomy 可行但门槛高

taxonomy 必须能解释实验现象，不能只罗列模块。七个正交维度：

  • Search control：fixed pipeline / single-agent adaptive / planner–executor / multi-agent / human-in-the-loop
  • Search space：keyword / dense vector / citation graph / author graph / web / full-text corpus / multimodal paper content
  • Evidence granularity：title-abstract / passage / section / table-figure / appendix / citation context
  • Search objective：relevance / recall / completeness / novelty / evidence verification / synthesis quality
  • Stopping policy：固定步数 / confidence threshold / marginal utility / coverage estimate / user-defined / no-answer detection
  • Memory：query / paper / evidence / citation graph / user preference / episodic search memory
  • Evaluation：output quality / evidence quality / trajectory quality / cost / robustness / calibration / reproducibility

有价值的 taxonomy 应能回答：什么情况下 query decomposition 有效？什么时候 citation traversal 比 dense retrieval 好？多 agent 是真提升 recall 还是只增加成本？更长的 reasoning trajectory 是否带来更多有效证据？agent 如何判断搜索已经足够？AutoResearchBench 已给出初步结论：增加搜索轮数和 tool calls 并不必然提升性能，关键是有效利用信息。

④ 题目与核心主张 —— 不要定成普通 survey

不建议用 A Survey of Agentic Literature Search（太宽，易与 Agentic RAG / Agentic LLM / Deep Research survey 重叠）。更有辨识度的题目：

  • Agentic Scientific Literature Search: Tasks, Evidence-Centric Architectures, Benchmarks, and Open Problems
  • From Retrieval to Research: A Systematic Study of Agentic Literature Search and Scientific QA

核心主张：agentic literature search 不是普通 web search 加一个 LLM，而是同时要求检索、全文证据验证、科学推理、集合完整性和停止决策的独立问题。支撑证据：普通 web benchmark 的高分不能代表 scientific literature search 能力 —— AutoResearchBench 中通用 web agent 与学术搜索表现存在明显差距。

⑤ 文章设计 —— 8 个研究问题 + 7 节结构 + failure taxonomy
研究问题
  1. RQ1：agentic literature search 与传统 academic retrieval、RAG、Deep Research 的边界？
  2. RQ2：现有系统实际执行了哪些搜索动作？
  3. RQ3：不同搜索策略在 recall / precision / completeness / evidence grounding 上的 trade-off？
  4. RQ4：agent 的推理、检索和 citation traversal 分别贡献多少？
  5. RQ5：多 agent 是否优于单 agent？
  6. RQ6：如何评价搜索过程，而不只是最终答案？
  7. RQ7：当前系统在哪些领域、任务和语料类型上失败？
  8. RQ8：如何设计可靠的 stopping、abstention 和 uncertainty estimation？
文章结构
  1. Problem formulation：topic search / paper identification / evidence retrieval / systematic filtering / comparative scientific QA / survey generation
  2. Taxonomy：planning / retrieval / browsing / evidence extraction / verification / synthesis / stopping
  3. Corpus and tool environment：arXiv / Semantic Scholar / OpenAlex / PubMed / citation graph / 全文 PDF-HTML / 表格图注抽取
  4. Systematic comparison：统一模型、统一检索库、统一 token/tool budget、统一 evidence format
  5. Benchmark analysis：ResearchArena / SurveyBench / AutoResearchBench / ScholarQuest / 其他 Deep Research 与学术搜索 benchmark
  6. Failure taxonomy：query underspecification / vocabulary mismatch / citation bias / abstract-only failure / false positive / missed key paper / unsupported synthesis / premature stopping / redundant search / temporal contamination / benchmark leakage
  7. Research agenda：evidence graph / interactive user modeling / dynamic corpus / multimodal paper search / process-level evaluation / cost-aware search / calibrated abstention / reproducible agent traces
⑥ 四类工作详解 —— 分别是什么意思、需要做什么含具体实现步骤（追问的完整回答）

核心区别：论文贡献从"总结已有工作"逐步升级到"验证已有结论、建立评测标准、提出新方法"。

类型 1 · 普通文献综述 —— 总结领域已有工作 顶会潜力较低

回答"这个领域有哪些问题、方法、系统和未来方向"。需要做：收集相关论文；明确研究范围（是否包括 Deep Research、academic search、scientific QA、automatic survey generation）；对现有工作分类；总结每类方法的流程与优缺点；整理数据集、benchmark 和评价指标；讨论挑战和未来方向。

确定范围→检索论文→筛选与去重→建立分类体系→比较方法与任务→总结挑战与趋势

可分类为：agentic RAG / academic paper retrieval / citation graph search / automatic survey generation / scientific QA / Deep Research / research-agent benchmark。主要产出：一套 taxonomy、一张代表性工作表、一份 benchmark-dataset 汇总、一份开放问题列表。

优点：工作量可控；适合快速进入新方向；不需要训练模型或搭建复杂系统。缺点：创新性容易不足；分类体系可能被认为主观；易与 Agentic RAG Survey、Agentic LLM survey、自动 survey 生成综述重复；顶会不满足于"整理得更全面"。更适合：arXiv survey、期刊综述、tutorial、workshop、领域尚无系统梳理时的早期工作。

类型 2 · 系统综述 + 统一 taxonomy + 大规模复现 —— 不仅总结，还验证结论 中等潜力

关键多做的一件事：在相同条件下实际运行各方法，检验"区别"是否真的带来性能差异。比较对象：BM25、dense retrieval、title/abstract retrieval、citation graph expansion、query decomposition、ReAct agent、Self-RAG、single-agent search、multi-agent search、automatic survey generation pipeline。给所有方法提供：相同文献库、相同用户问题、相同最大搜索轮数、相同 token/API 预算、相同输出格式。

统一测量：Recall@10 / Recall@100、Precision、nDCG、citation coverage、evidence correctness、answer completeness、search latency、token cost、tool-call 数量、重复搜索比例、提前停止比例。已有证据（ResearchArena）：agent 并不稳定优于简单关键词方法，一些 agent baseline 甚至低于 title-based retrieval。

可进一步回答：query decomposition 是否真提高 recall？citation traversal 是否更适合找经典论文？dense retrieval 是否更适合词汇不同但语义相关的论文？多 agent 提高 coverage 还是只增加成本？更长轨迹是否更好？agent 是否重复访问同一批论文？何时该停止？

四步实现

第一步 · 定义统一任务：给定研究问题，要求系统返回统一 JSON：

{ "papers": [...], "claims": [...], "evidence": [...], "confidence": ..., "search_trace": [...] }

第二步 · 准备任务集：从已有 survey 中提取主题、关键论文、引用关系、代表性方法、数据集、方法差异、实验结论。

第三步 · 实现 baseline：至少含 keyword、dense retrieval、citation-based、LLM query expansion、ReAct agent、一个 multi-agent 或 planner-agent 系统。

第四步 · 统一评测：不只评最终答案，还评搜索过程，并分析失败案例。例如：

Search Efficiency = Evidence Quality / Search Cost

贡献表述："我们在统一实验设置下比较了多类 agentic literature search 方法，发现现有 agent 的主要瓶颈不是生成能力，而是召回完整性、证据验证和停止决策。" 适合投 SIGIR / ACL / EMNLP / COLM / NeurIPS D&B / KDD。

类型 3 · 综述 + 新 benchmark —— 建立"这个领域如何被评价"的标准 高潜力

最重要的产出不是 taxonomy，而是新的、公开的、可复现的任务和数据集。已有覆盖：ResearchArena（discovery/selection/organization）、SurveyBench（survey 结构/内容/quiz answerability）、AutoResearchBench（精准找一篇 + 完整找一组）。可提出更聚焦 literature search + QA 的 benchmark，设计五类任务：

任务一 · 单篇论文事实问答："某论文使用了哪些数据集？最好的 ablation 结果是什么？" 要求：找到正确论文、阅读正文/表格/附录、给出答案、附精确证据位置。评价：answer correctness、evidence entailment、citation precision、citation completeness。

任务二 · 跨论文比较："比较三种方法在相同数据集上的性能并说明实验设置差异。" 要求对齐任务、对齐数据集、对齐指标、区分原始结果和复现实验、识别不可直接比较的情况——不能只分别总结论文。

任务三 · 条件式论文搜索："找出所有同时满足：2023 年以后、使用某类模型、在某数据集上、包含 OOD 实验、并与非 LLM baseline 比较的论文。" 与 topic search 不同之处在于要求集合完整性，用集合指标：

IoU = |Ŷ ∩ Y*| / |Ŷ ∪ Y*|　（Y* 为人工标注正确集合，Ŷ 为 agent 返回集合）

任务四 · 证据验证：给定 claim 和候选论文，判断哪些支持、哪些只部分支持、哪些矛盾、哪些证据不足。

任务五 · 搜索停止与 abstention：证据不足时明确回答"目前无法确认"或"没有找到满足全部条件的论文"——literature search 不应要求系统永远生成看似合理的答案。

一个好 benchmark 需要什么

多个研究领域；时间切分防训练数据泄漏；全文级证据；表格/图注/附录信息；正例、负例和边界例；多跳问题；需要 citation traversal 的问题；人工验证的 gold answer；搜索轨迹记录；统一工具接口；强 baseline；详细 failure analysis。AutoResearchBench 的启发：真正困难的科学搜索问题要求从全文细节、附录、表格和引用关系中整合证据，而不是只看标题和摘要。

贡献主张："现有 academic search benchmark 主要测相关性，现有 scientific QA benchmark 主要测给定文档上的回答能力；我们提出同时测量文献发现、全文证据验证、跨论文综合、集合完整性和引用可靠性的 agentic literature search benchmark。" benchmark 可被后续工作持续使用，比纯综述更有顶会潜力。

类型 4 · 综述 + benchmark + 新方法 —— 最完整、也最难 最有竞争力

结构：系统梳理已有工作 → 提出新 benchmark → 设计新 agent/search strategy → 在 benchmark 上证明有效 → 解释为什么有效。示例：Evidence-Centric Literature Search Agent —— 不是简单的"搜索 → 阅读 → 总结"，而是维护结构化 evidence state：

Research Question ├── Sub-question 1 │ ├── Candidate papers │ ├── Supporting evidence │ ├── Contradicting evidence │ └── Unresolved conditions ├── Sub-question 2 │ ├── Candidate papers │ ├── Supporting evidence │ └── Missing evidence └── Stopping status
研究问题→ 拆分约束→ 生成搜索计划→ 检索候选论文→ 全文证据抽取→ 验证支持与反驳→ 更新证据图→ 存在未解决约束？是 → 回到「生成搜索计划」否 → 生成答案→ 引用与不确定性检查
五个可能的新方法
  • 方法一 · Evidence Graph：每个 claim 作节点，论文片段作 evidence node（supports / contradicts / partially supports / related but insufficient）。agent 不直接把所有文本塞进 context，而是先构造证据图，再基于图回答。
  • 方法二 · Coverage-Aware Search：估计当前搜索覆盖了哪些子方向（方法类别、数据集、研究团队、年份、citation cluster、负面结果）；某方向 coverage 低时自动发起新搜索，而不是重复原 query。
  • 方法三 · Cost-Aware Stopping：每次新搜索前估计边际收益，低于阈值即停止并输出当前不确定性：
    Utility(q) = E[new evidence from q] / search cost(q)
  • 方法四 · Claim-First QA：先把用户问题拆成一组可验证 claim，分别检索和验证，避免一次性生成容易幻觉的大段答案：
    Claim 1: 方法 A 使用了数据集 X Claim 2: 方法 A 在 X 上优于 baseline B Claim 3: 该结果来自主实验而不是 ablation Claim 4: 方法 A 与方法 C 的比较是公平的
  • 方法五 · 主动反例搜索：普通 agent 只搜支持当前假设的证据；更可靠的系统应主动问——有没有论文报告相反结果？有没有同名但不同定义的方法？有没有边界条件不满足的候选？这个 claim 是否只在某个数据集成立？把 literature search 从"找支持材料"提升到"证据审查"。
需要证明什么（消融）

不能只证明"我们的答案更好"，还要做：没有 evidence graph 会怎样？没有反例搜索会怎样？没有 coverage estimation 会怎样？没有 stopping policy 会怎样？单 agent 与 multi-agent 差异？相同 token budget 下是否仍有效？搜索时间和成本是否可接受？

⑦ 行动建议 —— 两阶段路线与推荐切入点
第一阶段 · 先做"系统综述 + 小规模复现"

先不要立刻构建很大的 benchmark：明确 agentic literature search 的定义 → 建立 taxonomy → 选 5–8 个代表性系统 → 在 3–5 个领域做小规模实验 → 找出最稳定的 failure modes → 再决定 benchmark 应该测什么。避免一开始凭直觉设计 benchmark。

第二阶段 · 升级为"benchmark + 方法"

根据第一阶段的失败模式，选一个核心问题：citation completeness / evidence verification / exhaustive search / cross-paper comparison / stopping and abstention / interactive user intent clarification，围绕它构造 benchmark 和新方法。

最推荐的切入点：Evidence-grounded and completeness-aware agentic literature search —— 同时关注：找到正确论文、找全关键论文、找到支持结论的精确证据、明确哪些地方仍然无法确认。比泛泛做"一个能搜索论文的 agent"更容易形成清晰的 scientific contribution。

理由（现有工作暴露的空缺）：SurveyBench 发现自动 survey 往往结构流畅但技术细节、综合推理和核心思想抽象不足；AutoResearchBench 显示科学文献搜索中的完整性和细粒度验证仍然很困难。

B · Agent-Centric Literature Retrieval ICLR / NeurIPS / SIGIR / ACL / EMNLP

传统 Retriever 优化 query–document 局部相关性；Agent-centric Retriever 应优化文献对最终任务的效用：是否提高最终答案正确率、是否增加新的证据维度、是否消除或暴露证据冲突、是否帮助生成下一步检索词、是否提高综述覆盖率、是否支持最终主张并提供可验证引用。与选题讨论的"Evidence-grounded & completeness-aware"切入点重合度最高

C · Evolving Scholarly Graph Mining KDD / WWW / WSDM / SIGIR

数据 = 论文全文 + 引用图 + 作者机构图 + Method/Dataset/Benchmark 实体 + 发表与更新时序 + 用户阅读收藏查询轨迹。任务：新论文冷启动推荐、emerging topic detection、研究方向演化建模、方法-数据集-benchmark 关系抽取、个性化兴趣更新、缺少引用信号时评价新论文价值、从文献流中发现研究空白。

D · Dynamic Multimodal Literature Data System VLDB / SIGMOD / ICDE / CIDR

统一管理 PDF 与结构化全文 + Chunk + 图表 + 多版本 Embedding + 引用图 + 元数据 + Agent 查询与证据轨迹。研究点：增量解析与 Chunk 级更新、关键词/向量/图/元数据混合查询、Embedding 模型在线迁移、多版本论文与 time-travel query、RAG 数据血缘与结果可复现、Agent 工作负载驱动的索引优化、持续更新时的一致性吞吐延迟成本。

LAB-Bench（第一代，8 个子基准）：LitQA2（检索全文并回答）、SuppQA（补充材料）、FigQA（图像图注）、TableQA（表格）、DbQA（生物数据库）、ProtocolQA（实验协议排查）、SeqQA（序列计算）、Cloning Scenarios（分子克隆设计）。接近"标准化考试"：多选为主、易自动算 Accuracy / Precision / Coverage、公开约 80%。

LABBench2（第二代）：约 1,892 个真实科研任务、11 个大类；因 FigQA2 / TableQA2 分 image / PDF / retrieval 三种模式，排行榜上体现为约 15 个子基准。

💡 Idea 生成

Literature项目或者系统/待归档/ · 4 篇 · 全部精读+代码审计（2026-08-04）
点开阅读 ▾

很多 literature 工作最终是服务于 idea 生成的——这一簇专门看「idea 生成系统是怎么做文献的」：四条技术路线，文献分别被组织成引用链（CoI）、概念网络（Deep Ideation）、端到端训练语料（CycleResearcher）、agent 人设+新颖性对照库（VirSci）。每篇均已通读论文全文+代码并写成精读页（论文原图 + 论文↔代码审计 + OpenReview 评审对照）。

Chain of Ideas (CoI Agent) 文献→引用链

DAMO Academy 等 · ICLR 2025 Reject (5/5/5/8) · arXiv:2410.13185

把相关文献按发展脉络组织成链（anchor 论文向前 LLM 读全文找源头、向后按引用+相似度延伸），让 LLM 沿趋势外推 idea；配套 Idea Arena（成对对战+ELO）评价协议。审计发现：向前扩链的 LLM 相关性闸门判错对象（恒通过），Idea Arena 评测代码整体缺失、主实验不可复现。

CycleResearcher 文献→训练语料

Westlake NLP 等 · ICLR 2025 Poster（带保留接收）· arXiv:2411.00816

开源 LLM 全循环：CycleResearcher 从 references 直接写完整论文，CycleReviewer 模拟评审给 RL 奖励迭代偏好训练。meta review 批评极重：初版实验结果全是幻觉仍拿高分、对自产 reviewer 优化后再用它评估——reward hacking / LLM-judge OOD 失效的活教材。审计发现：repo 只是推理壳，SFT/SimPO 训练与 rebuttal 承诺的 o1 端到端流水线均未发布；"两轮输入"名实不符（实验结果由模型一口气编造）。
